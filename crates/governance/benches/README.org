#+TITLE: Owned Source Validation Benchmark
#+LANGUAGE: en

* Workload

Clone concrete source records and check original selection/profile/plan bindings.
The capture-and-bind case also retains an immutable original owner,
candidate cloning/validation and complete native record equality.
The lane roundtrip additionally measures bounded admission, one blocking-owner
handoff, independent original binding and future delivery. Its identity callback
uses concrete records; worker/runtime construction and drain are outside timing.
Catalog roundtrips use one or 64 independently validated family entries, exact
source-identity/epoch observation matching and a selected name. They include
lookup, shared immutable-original retention, bounded queue and result binding.
Catalog construction and compiler/runtime construction/drain are outside timing.
The identity callback returns the immutable original; actual Scheme/Cedar work,
live source-authority observation and final execution checks are excluded.

* Measurement boundary

This includes existing body/profile commitment validation. It excludes VM startup,
AA execution, SDK root conversion, gRPC and provider sends. It is not native VM
acceptance or Gateway throughput. Thirty samples use existing collection settings.

* Entrypoints

=cargo bench -p weaver-governance --bench gateway --locked --offline=.

* Native conversion diagnostic

=cargo bench -p weaver-governance --bench scheme_conversion --profile dev --features scheme-qualification --locked --offline --config 'profile.dev.package."*".opt-level=3'=.

This additional target uses the real qualification graph and one naturally
drained VM. Its explicit development profile preserves the prohibition on
shipping the qualification application in a release image. It is a warm
conversion diagnostic, not optimized production Gateway throughput.
The command optimizes external dependencies, including both the SDK and its
SIMD UTF-8 validator, while retaining the development-only qualification owner.
An entirely unoptimized dependency build can dominate Unicode validation cost;
keep that control separately and never compare its latency with release claims.
The ordinary gateway benchmark and production build profiles are unchanged.

Thirty samples compare the retired temporary-Scheme-bytevector conversion with
the upstream direct owned-string encoder on identical retained roots, for ASCII
and Unicode/NUL at three sizes. Both paths validate UTF-8. Each pair runs in the
same owner and process; fixed ordering still permits drift, so repeat the whole
target before attributing small differences. Source roundtrip includes bounded
construction, materialization, validation and original binding. Neither this
case nor the string comparison publishes Policy, authorizes bytes or releases
budget. VM startup and root construction are outside string timings; original
capture remains inside the source roundtrip. This target is separate from the
ordinary cross-package benchmark inventory and does not qualify that inventory.

The separate assessed_capture case invokes the actual approved AA producer and
its inert Cedar preflight, then materializes and binds the result to an original
captured before the call. It retains the real policy ABI anchor. Thirty flat
samples cover this more expensive operation; the measurement target is not a
per-call deadline. It still excludes authoritative publication, final Policy
evaluation, provider transport and Gateway throughput.
