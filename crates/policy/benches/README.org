#+TITLE: Cedar validation and evaluation
#+LANGUAGE: en

* Workload

Typed schema validation; warm compilation with a fresh authorization decision; sixteen-source compilation-cache churn.
Named materialized PolicySet JSON schema validation and actual fixed-SPEC
schema-bound candidate replay and parent-bound revision replay bring this package
to six declared cases. Revision replay binds exact predecessor bytes to the
authority-captured head and both PolicySets to the actual upstream manifest.
The complete four-case upstream manifest and receipts are prepared before timing;
replay includes all four cases, while only two refer to the selected candidate.
Neither measured success proves no-gain or producer authenticity.

* Measurement boundary

Actual Cedar parse/schema/evaluation work. A warm compilation cache never substitutes for a fresh authorization decision.

* Entrypoints

Run this package with =cargo bench -p weaver-policy --all-features --bench gateway --locked --offline -- --noplot=.
Run the complete measured matrix with =go run ./go/cmd/weaver-dev bench=.
Criterion is inherited from the workspace as a development dependency.
Each case uses thirty samples, one second of warm-up and two seconds of requested measurement.
Compilation or a smoke invocation alone is not a measured baseline.

The Go runner retains environment logs, source hashes, fresh per-case Criterion
data and an English Org summary. Missing cases fail artifact collection.
Regression warnings remain evidence even when the benchmark process succeeds;
these measurements do not establish a production latency or throughput target.

See [[file:../../../docs/50-59-research-program/59-provider-rpc/59.05-benchmarks.org][the workspace benchmark contract]] for the complete matrix and interpretation rules.

* Per-effect context construction

=policy/context_json_{local,shared}= and
=policy/context_literal_{local,shared}= run in the same Criterion binary, with
identical immutable facts and current-effect inputs. The JSON reference is
compiled only into tests/benchmarks. The literal case includes the production
context-construction source directly, without exposing a public benchmark API.
Both construct actual Cedar SDK Context values. These cases measure construction,
not authorization, persistence, queueing, network latency or Scheme preparation.
The existing current-decision case still performs a new error-free Cedar decision.

=go run ./cmd/weaver-dev bench-execution= from =go/= adds complete Rust PBT,
real Go/Cedar/Rust fault integration and fresh published-source streaming samples.
It does not build or invoke Scheme. The earlier =bench-runtime= entry remains
available for the separate complete compiled-Scheme source chain.
