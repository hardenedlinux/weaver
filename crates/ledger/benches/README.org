#+TITLE: Durable authorization and publication
#+LANGUAGE: en

* Workload

Fresh admission; consumption and dispatch burn; idempotent admission; atomic publication commit; exact publication replay; historical outcome lookup.
Atomic task/profile registration and exact task replay use one or 256 tasks
sharing the same immutable profile. Durable staging plus decision and trusted-host
review registration plus final CAS are measured separately.
The named-Policy case includes actual SPEC replay, local review registration and final
CAS for the complete named-Policy fixture. Its store/stage fixture is outside timing.
Persistent source-key handoff and source-authenticated publication are also measured.
Initial empty-store enrollment is outside timing;
retained key history, actual source checks, atomic receipt and final CAS are timed.
The parent-bound revision case measures revision replay, registration
and final CAS. Initial parent publication and staging are outside timing.
The review case captures its actual parent and stages the requirement outside
timing; registration persistence, exact artifact validation and final CAS are timed.
No external producer authentication, solver or independent anchor is measured.
Two additional cases measure first source enrollment against the actual
application-table catalog, with zero or 32 empty extension tables. Database
creation and extension DDL are outside timing; catalog discovery, row-existence
checks and the atomic initial key/binding commit are inside. This scan is absent
from already-enrolled source checks and from the provider message/send path.
The cases do not measure recovery from an empty whole-store rollback image or
provide evidence of an independent retained root.

* Measurement boundary

=ledger/shared_exposure_dispatch/{1,8,64}= measures consumption, the durable
dispatch burn and the current final guard with that many retained provider
reservations in one family. Exact original tasks, plans and reservations are
created outside timing. The shared projection scans request, message and
provider reservations and verifies their execution-kind claims and original
budget. These fixtures expose family-size cost; they do not measure mixed-kind
throughput, external network IO or an independently anchored recovery protocol.

MRR Data/Turso FULL/WAL operations and current authorization. Fresh database setup and object destruction are outside timing. Serial measurements do not establish concurrent throughput or crash recovery.
Profile replay includes the retained original-task semantic floor and registry
join. The one/256 fixtures are populated before timing; they expose history-size
cost without including setup in the measurement. Index-plan tests verify bounded
range seeks separately; a query plan is not a latency benchmark.

* Entrypoints

Run this package with =cargo bench -p weaver-ledger --all-features --bench gateway --locked --offline -- --noplot=.
Run the complete measured matrix with =go -C go run ./cmd/weaver-dev bench=.
Criterion is inherited from the workspace as a development dependency.
Each case uses thirty samples, one second of warm-up and two seconds of requested measurement.
Compilation or a smoke invocation alone is not a measured baseline.

The Go runner retains environment logs, source hashes, fresh per-case Criterion
data and an English Org summary. Missing cases fail artifact collection.
Regression warnings remain evidence even when the benchmark process succeeds;
these measurements do not establish a production latency or throughput target.

See [[file:../../../docs/50-59-research-program/59-provider-rpc/59.05-benchmarks.org][the workspace benchmark contract]] for the complete matrix and interpretation rules.

* Original reservation bytes

=ledger/original_reservation_bytes/<count>/<bytes>= crosses one, eight and 64
retained provider plans with 128-byte and 16-KiB prompt content. A single-plan
512-KiB case covers a larger original record without conflating record count and
body size. The complete JSON body also contains the fixed provider envelope.
The guard reads original ceilings from retained JSON; family-size-only fixtures
cannot characterize that cost.

All original task registration and reservation inserts occur before timing.
Consumption, durable burn, current final-use authorization and hold observation
are timed. The callback performs no network IO. These are local durable-path
measurements, not pure SQL microbenchmarks, provider throughput or evidence of
snapshot-rollback protection. Report exact build mode and host conditions;
compare revisions only with a matched source and measurement protocol.

* Multi-message retained manifests

=ledger/stream_manifest_guard/{1,8,64}= retains that many message commitments in
one stream claim. Source task, manifest, all message rows and custody are created
outside timing. The timed path consumes one range, evaluates the current exact
member/digest/ceiling join and calls a local complete-range writer. The entire
original shared hold remains retained. This measures the deciding path with a
multi-member root; it does not measure socket throughput, fixture admission,
refunds or independent rollback recovery. Use the unchanged thirty-sample,
one-second warm-up and two-second requested measurement configuration.

* Durable range tail

=ledger/range_tail_guard/{0,8,64}= retains that many completed ranges before
timing. Consumption and final guarded use validate the indexed latest tail
against the original message cursor. Setup is outside timing; the callback is
local, with no network IO. All cases use the same MRR Data / Turso driver and
unchanged thirty-sample protocol. These results do not establish a speedup
over the retired engine or concurrent throughput.
