* Checked artifacts and scope

[[file:quint/LogicalMessageAuthority.qnt][LogicalMessageAuthority.qnt]] is an executable Quint model with normal
transitions and separately selected counterexample controls.
[[file:lean/LogicalMessageAuthority.lean][LogicalMessageAuthority.lean]] defines a transition relation, reachability,
step preservation and inductive safety proofs. These are actual checked formal
artifacts. They do not implement the gateway or change dependency pins.

The unit of reasoning is one already owner-resolved logical message, with
multiple issuance identities, two competing candidate workers in Quint, a
sticky claim, transport incarnation, late evidence and a unit upper-bound hold.
Lean quantifies over arbitrary natural-number issuance keys, workers, revisions
and incarnations, and all finite reachable traces. Quint uses four scoped keys,
two issuer incarnations, two workers and three transport incarnations. The
initial empty revision is an admissible initial worker snapshot; subsequent
consumption requires a current capture. An effect observation is absent from
the consume transition: consuming unknown still advances revision and the
independent consumption count. The execution root can remain constant throughout
this abstraction; it is never used as the state-identity guard.

One offer denotes the irreversible offer of one complete semantic message to
the transport. It is not a count of write syscalls, delivered bytes or successful
remote applications. Range/cursor refinement, partial buffer ownership and
transport fencing remain separate obligations. This conservative machine cannot
resume a claimed message on a different stream, even if it had not yet offered.

to two canonical semantic intents, many aliases and one shared weighted budget

reuse, new premises, action/theorem correspondence and executable controls.
[[file:evidence/shared-identity-budget-2026-10-19.org][Its separate evidence receipt]] binds the new artifact bytes and results;
the earlier receipt below remains unchanged.

Lean imports LogicalMessageAuthority and proves that each product transition
projects to a previous message Step or a stutter. It adds alias soundness,
frame preservation, shared weighted conservation and a common history gate.
The domain has two canonical intents; aliases, revisions, workers, issuer/
stream coordinates, costs and capacity are unbounded natural values in Lean.
It is not an arbitrary-cardinality or multi-domain theorem. Immutable owner
intent/payload/domain admission and physical enforcement remain premises.

Quint uses two intents, four aliases, two workers, four scoped nonce indices,
two issuer selectors and three stream incarnations. Unequal costs are one and
two units. Its normal initializer funds three units; tightInit funds two.
Independent semantic claim/offer counters detect duplication even when each
misresolved local record remains individually affine. The guide's earlier
single-message limitations describe that artifact's scope; the new product
addresses aliases and shared accounting without claiming source refinement.

* State and action correspondence

All corresponding fields have the same meaning. Quint finite maps become total
functions in Lean. The finite token domain embeds into natural numbers; token
values stand for complete namespaced issuance identities, not bare wire nonces.

| Quint action | Lean Step constructor | Meaning and guard |
|--------------+-----------------------+-------------------|
| register | register | Idempotently retain the same logical reservation and restrictive history |
| issue(t) | issue | Record an admitted issuance without resetting message state |
| capture(w) | capture | Store the current authoritative revision; creates no effect authority |
| consume(w,t) | consume | Atomically require issuance, current revision and zero consumption; increment the independent count and revision |
| claim(t) | claim | Require consumed issuance, held reservation and no existing claim; increment claim count and bind original token/stream |
| offer | offer | Require the original live stream, a claim, zero prior offers and no retirement |
| rotate | rotate | Change issuer incarnation only |
| reconnect | reconnect | Change transport incarnation only |
| observe(t) | observe | Append admitted evidence bound to the original claim; no consume/claim/send change |
| retire(t) | retire | Admit original emitter retirement evidence separately |
| finalUsage(t) | finalUsage | Admit final-cost/no-future-accrual evidence separately |
| settle | settle | Move the one-unit hold to a charge only with all three evidence facts |

Quint additionally restricts issuance to the current finite issuer namespace;
Lean permits any admitted key. Thus Lean proves safety for a more permissive
issue relation. Quint bounds rotate/reconnect; Lean does not. This is a reviewed
abstraction correspondence, not a machine-checked Quint-to-Lean translation or
source refinement theorem. No equality of file hashes establishes semantics.

* Properties with actual theorem names

| Quint invariant / observable relation | Lean theorem | Scope |
|--------------------------------------+--------------+-------|
| safety | initial_safe, step_preserves_safe, reachable_safe | Initial and every declared transition preserve the inductive invariant |
| nonceSafety | issuance_consumed_at_most_once | Independent count per admitted, fully scoped issuance never exceeds one |
| claimSafety | logical_message_claimed_at_most_once, claim_origin_is_sticky | One canonical message cannot acquire another claim or replace its origin |
| messageSafety | logical_message_offered_at_most_once | At most one abstract complete-message transport offer |
| historySafety | history_survives_reserved_work, history_is_monotone | Registered restrictions survive issuer/stream changes and late evidence |
| settlementSafety | settlement_requires_retirement_and_final_usage | An outcome alone cannot settle |
| Unit hold partition | budget_partition, unknown_retains_hold | Held plus charged equals the reserved unit; uncertainty does not free it |
| Stale worker revision after consume | consume_invalidates_captured_revision | Unknown consume invalidates a previously captured revision |
| Original claim versus new stream | reconnect_preserves_claim_origin, old_stream_cannot_offer | Reconnect does not transfer the old transport binding |
| Observation versus execution | late_observation_preserves_execution | Observation does not reset sends, claim or settlement |
| Retired execution | retirement_is_monotone | An admitted retirement cannot be reversed |

The Safe invariant counts actual declared consume and claim transitions;
counts are incremented rather than overwritten with a Boolean. This matters:
otherwise a duplicate operation can be hidden behind a permanent true marker.
The one-unit accounting proof has no refund or top-up transition; it does not
prove parent escrow allocation, cross-message conservation or real pricing.

* Positive and negative controls

The first three tests are legitimate lifecycle controls. The last five select
invalid transitions excluded from step and assert the resulting invariant
violation. A passing negative test means that the bad design has a concrete
counterexample. It does not mean the bad transition was admitted to the safe
machine. Historical counts remain intact in mutations.

| Test | Evidence |
|------+----------|
| normalLifecycleTest | Actual offer and outcome retain the hold until retirement plus final usage; settlement then succeeds |
| concurrencyTest | Both workers capture the same revision; the winner spends and makes the other snapshot stale |
| rotationAndReconnectTest | A second admitted issuance can be consumed without replacing the first claim; old observation is admitted after reconnect, with hold retained |
| rootOnlyCounterexampleTest | Ignoring revision and spent membership consumes the same issuance twice despite an unchanged abstract root |
| freshNonceCounterexampleTest | Removing only the unclaimed guard lets a new issuer/key acquire a second logical claim |
| reconnectCounterexampleTest | Removing that guard lets the same issuance acquire another claim on a new stream |
| lateObservationCounterexampleTest | A completion path that reopens the claim contradicts the historical claim/offer invariant |
| prematureSettlementCounterexampleTest | Treating an outcome as settlement violates separate retirement/final-cost requirements |

* Trusted premises and remaining refinement

Scheme must resolve the logical key and immutable semantic binding before any
modeled transition. Caller IDs, content equality and new nonces do not establish
that identity. This model fixes one key; it cannot prove that a resolver prevents
an attacker from placing the same intent in a second machine. Registering a
legitimate distinct message, cross-key isolation and shared parent capacity need
the product extension described above; implementation refinement remains
pending.

Issue presupposes authentic, error-free Cedar admission, exact request/entity
projection, current source guards and actual original-issuer consumption at the
appropriate runtime join. consume abstracts an authoritative storage transaction;
it does not prove the existing pure P13 call is atomic. Observer authentication,
original claim/stream/attempt/evidence binding and actual emitter retirement
are trusted input contracts. A matching integer token is only their abstraction.

Reconstruction must preserve every durable field. There is deliberately no
restore-empty or rollback transition. These proofs do not establish storage
persistence, snapshot lineage, entropy, stop/drain, receiver fencing, scheduling
fairness, termination, eventual delivery, or liveness. Old-worker physical
emission requires the separate broker/receiver qualification contract. No theorem
here imports cedar-poo-spec or POO Flow, or proves their native ABI/projection;
existing owner laws guide the specification and retain their original premises.
