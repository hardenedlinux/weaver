* Actual composition and evidence boundary

=State.floorState= is the actual =LlmAdmissionFloor.State=. =Ticket= binds full exact
proposal, actual floor receipt, account image/journal, worker, source generation,
source/account qualification and aggregate source-owner revision. =validate= needs
authentic current state, floor qualification and source allowance. =commit= needs
the exact current ticket, current source allowance and an actual floor step that
publishes that exact proposal. =advance= permits actual non-publication floor
steps, including financial progress and local recovery, without creating a new
floor record. =sourceChange= advances the governed external dependency revision;
=restart= drops volatile validation.

=floor_projection= and =actual_floor_composition= connect arbitrary finite guarded
runs to the real initialized floor/handoff/WAL/account/source chain. There is no
second fake account or financial delta counter. =publication_no_financial_effect=
uses the actual prior control-publication theorem. Original reservation uniqueness,
unknown holds, original-operation result uniqueness and pending preservation use
the actual inherited proofs.

=final_commit_requires_current_join= characterizes the actual determining step's
pre-state: a matching complete ticket and current source allowance for its exact
published proposal. It does not infer native atomicity from the ticket. The
selected recoverable source-owner custody protocol must serialize the actual
mutation/commit order; native implementation and progress remain acceptance gates.

Quint imports both the actual floor and actual account modules. They share the
same account state =a= in the ITF product. =financialCommit= is the actual inherited
settlement of the accepted second original frame, advancing the actual account
image/journal while the floor head stays unchanged. The decoder verifies that
same-prefix/different-account counterexample, its original spent nonce/exposure,
and real account applications/holds. Directly imported account controls are
counted separately from new controls and floor controls.

External source/Policy/history mutation is the qualified aggregate revision in
this product. It preserves financial authority and provider execution state; it
is not fabricated source-completion evidence. Native qualification must establish
that every relevant dependency mutation participates and that its revision and
namespace cannot roll back independently of current-read authority. Lean also
binds actual governed source generation/qualification. The finite fixture keeps
the inherited source generation fixed and varies the external aggregate revision.

Storage-only Quint actions use the imported authenticated pure financial read
with explicit =f'=f= hold. This refines an actual non-publication floor transition
and the new join step. It cannot manufacture provider delivery or usage receipts.
=lastChecked= and =attempted= are mutation-test observations, not production permits.

* Counterexamples and independently decoded facts

| Counterexample control | Independently required observation |
|------------------------+------------------------------------|
| sameFloorAccountJoinCounterexampleTest | Cached and attempted floor heads match, but actual journal grows from one to two and authoritative account changes before a broken publication |
| sourceDeniedJoinCounterexampleTest | Account/floor unchanged; aggregate source revision advances to denied while an imported floor publication bypasses the new gate |
| sourceABAJoinCounterexampleTest | Source denies then allows again; current allowance is true but old ticket revision zero differs from current two |
| differentIntentJoinCounterexampleTest | Append ticket is used to publish a different original cut operation under the same starting state |
| lostReplyJoinCounterexampleTest | Original append result is resolved, but a broken consumer treats the result as reusable join permission |
| restartJoinCounterexampleTest | Volatile ticket has been cleared; actual imported floor publication proceeds only in the broken variant |
| staleWorkerJoinCounterexampleTest | Owner advances; old-worker proposal attempts to use the new context without a valid original current join |

Unsafe actions are excluded from =step=. Five mutations deliberately call actual
imported floor operations that remain valid absent the new source join: same-floor
account change, source denial, source ABA, different original operation and
cleared-ticket restart. This demonstrates
the added coordination obligation. Descriptor-only lost-result/stale-worker
mutations do not claim the earlier floor/account guards were bypassed; they show
invalid permission reuse while those earlier guards still protect actual effects.
The different-operation mutation executes the actual alternative cut publication.

The same-floor account trace legitimately settles its known original usage through
the actual account gate before exposing stale join reuse. Its changed hold is not
an erroneous refund. Other traces preserve the pending original hold. The decoder
checks that distinction instead of demanding an unchanged account for every test.

* Native acceptance gates

| Gate | Required executable evidence |
|------+------------------------------|
| Same floor/account race | Pause after validation, perform real original account settlement, leave floor unchanged, resume final CAS; reject/revalidate old account image |
| Source invalidation | Deny/allow ABA, Policy/history mutation, source generation/fence and unmapped dependency changes; every relevant mutation participates in current revision qualification |
| Custody and actual CAS | Pause immediately before remote determining CAS; race source/account mutation and owner takeover; one authenticated serialization order, no queued unfenced continuation |
| Unknown outcome | Lose commit response across source-owner restart; recover original join intent/custody and determining result before accepting progress or releasing constraints |
| Original retry | Reconnect/SDK retry resolves one original operation; no duplicate admitted segment, new family, new budget domain or repeated financial application |
| Exact attempt | Rebase same original intent with changed before/after image; old ticket rejects and new current validation is required |
| Retained pending state | Old worker recovery and inconsistent local snapshots retain exact original tails, claim/profile and unknown holds; no inferred abort from local absence |
| Current native facts | Caller-supplied revision/allow boolean, replica-local old prefix or valid historical signature cannot authenticate current Host input |
| Source domain recovery | Source revision/custody survive declared rollback or remain closed; no counter reuse, empty namespace or exhaustion wraparound |
| Final send | Join/floor/query instrumentation shows no provider IO; actual broker/executor still applies current grant, Policy/history, owner and budget gates |

The abstract joined commit assumes recoverable native custody. This does not
prove a distributed transaction protocol, quorum implementation, codec/IO/ABI
correctness, arbitrary-account product, general external dependency coverage,
pending-owner continuation liveness, archive pruning, provider exactly-once
or performance. Prior one unresolved cut and one uncommitted settlement frame
per account lane remain inherited restrictions.
