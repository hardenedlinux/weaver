* Atomic account model and actual source composition

The Lean account image has balances indexed by account, immutable applications
indexed by application ID, consumed reservations indexed by original reservation,
per-reservation holds and a revision. =commit= performs one =applyImage= transition
and appends that exact result. =commit_is_atomic= characterizes every change in
financial revision. There is no guarded constructor that inserts only an ID,
changes only a balance or resets an original reservation.

=initialized_safe= proves conservation, one write per original reservation, original
application/reservation linkage, exact image equality before visibility and hold
retention for unconsumed reservations. =journal_revision= and
=journal_prefix_retained= separately connect financial commits to the append-only
record sequence. Counter maps are proof monitors; uniqueness gates use immutable
application and reservation tables, never a restored counter.

=OriginalReady= connects a globally selected original reservation key, actual
=LlmAttemptLedger.Attempt= bound and actual =LlmExecutionReconciliation.State=
metering. =actual_reconciliation_has_terminal_and_bound= reuses the preceding
initialized product invariant. =commit_joins_actual_reconciliation= joins an actual
account commit with that actual source run under an explicit sourceReady binding.
The binding must authenticate full root/profile/domain/receipt correspondence;
the compact numerical projection does not supply native authenticity.

=unknown_source_retains_original_hold= proves that, when every account commit path
for the selected key must refine that unknown original source, the reservation
cannot be consumed and its hold remains unchanged. Other qualified reservations
can settle. This requires the binding for all relevant sourceReady paths, not just
a validation callback that an alternative account writer can bypass.

The account and reconciliation models remain separate typed products joined by
this explicit per-commit mapping. They do not model a native transport, database
and quorum as one atomic action. The account owner receives the full account state
for sourceReady; source invalidation advances a monotonic source generation and
closes source qualification. An old proposal stays stale even if source qualification
is later restored. Current owner is checked again at commit, independently of the
proposal's original preparation.

The native anti-rollback premise is isolated in =prefixAuthentic= and the transition
universe: only financial commit advances authority, local restore never changes it,
and owner/source generation stamps cannot be restored backwards. The unsafe
co-rollback control deliberately breaks that premise. An independent monitor keeps
already exposed credits for the test; that monitor is not a production authority.

* Earlier Weaver proof reuse boundary

The existing =SettlementAnchorRecovery= model already separates protected authority
from a restorable local image and treats application plus immutable receipt as a
logical transaction. =GateConsumptionPersistence= retains unresolved gate burns and
requires an archived actual result before confirmation. =WriterSettlementClosure=
separates authentic terminal evidence, final usage and settlement.

Those mechanisms guide this extension; their sealed sources and receipts stay
unchanged. This runner does not claim to import their entire driver/hardware
lineage into the current AI Agent Gateway product. The new executable refinement
adds explicit per-reservation hold and balance mutation, with the actual category-23
source product as its direct Lean dependency. Older write counters alone are not
an implementation proof of atomic balance persistence.

| Native gate | Required evidence before implementation acceptance |
|-------------+----------------------------------------------------|
| Atomic financial commit | Kill/restart at every WAL/transaction point; recover either full ID/reservation/hold/delta record or no record; never a split |
| Durable acknowledgment | Lose response after commit; query exact original outcome and expose one credit only |
| No premature credit | Persist a draft and fail before protected commit; no account API, grant or cache exposes the draft's available balance |
| Independent prefix | Restore account/worker and storage snapshots behind committed authority; prove current prefix is independently governed or remain closed |
| Complete recovery image | Restore each ID/hold/balance/source/usage participant at different positions; no mutation or balance visibility until exact reconciliation |
| Shared account concurrency | Same reservation/different IDs, same ID/different bodies, and different reservations/same account revision |
| Current fences | Old worker with fresh image, old prepared transaction and source generation change between preparation and final commit |
| Unknown budgets | No terminal usage, contradictory late usage and lost source application; unknown original hold survives other qualified settlements |
| Full funding reconciliation | Initial finite reservation holds agree with aggregate booked funds, source capacity, units and original account domain |
| Complete mediation | Every real account delta/refund/new-grant read passes the qualified account authority; SDK adapters have no bypass writer |

The local results close the selected logical account contract under these premises.
Native storage, distributed prefix durability/currentness, provider receipt truth,
arbitrary-many-source composition and recovery liveness remain separate evidence.
