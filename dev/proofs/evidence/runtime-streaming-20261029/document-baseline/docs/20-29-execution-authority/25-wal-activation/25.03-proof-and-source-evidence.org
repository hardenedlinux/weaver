* Actual composition and visibility proof

The product contains the actual =LlmAccountCommit.State=, a local WAL, retained
complete candidates, a current confirmation and an activation flag. =core_projection=
constructs actual account runs for prepare, protected commit, owner/source changes,
image install and recovery. Other staging/repair/readback steps stutter the account.
=actual_account_composition= extends an initialized account prefix through arbitrary
finite product runs, rather than reinitializing the financial state at recovery.

The inherited actual account theorem proves one original reservation consumption,
account conservation and immutable application bodies. Its actual reconciliation
mapping supplies source terminal/final usage and unknown-original-hold retention.
No independent "release counter" is substituted for that account history.

=initialized_live= proves that every active state has a qualified core, exact
current account image, qualified source, a confirmation matching the complete
current head/journal/owner/source generation and full anchored WAL prefix coverage.
=visible_balance_is_current= extracts that gate. =truncated_wal_cannot_be_visible=
excludes a missing anchored record even when a local revision looks correct.

=financial_change_requires_anchor= characterizes every change in financial revision:
it requires a retained complete candidate, the actual final account Ready predicate
and the exact account image transition, and it closes visibility. Thus a late
commit between observation/replay/install or after an earlier activation invalidates
the earlier view. Native final consumers must refine this authority order; a remote
cached activation bit is not an independent grant.

=accepted_candidate_retained= is deliberately conservative for this reference: local
WAL restore does not alter the independent pending candidate. The model retains
candidates even after completion. Safe garbage collection would need a proof that
the full committed result or a terminal rejection remains independently queryable;
this product does not authorize deletion of the only outcome evidence.

* Native and model boundaries

Local WAL frames are typed complete records, not modeled byte arrays. The flush
and candidate predicates stand for native atomic framing, durable completion and
complete immutable retention. Malformed/truncated record controls exercise missing
or altered typed records; they are not a proof that a native parser rejects every
torn byte sequence. Native crash injection and WAL-format qualification remain gates.

Protected journal and fence fields are not restored from local images. The model
has no guarded action that truncates the protected prefix. The independent prefix
predicate must authenticate the actual current non-forking authority, including
complete bodies and stamps. An old replicated response or an equal numeric position
cannot satisfy that premise by assertion. A co-rollback counterexample breaks the
premise deliberately and keeps an independent test monitor of already committed
credits; that monitor is not production authority.

The active flag represents authority-serialized state. Immediate clearing in the
model must be implemented by a final CAS/current-prefix check; it does not prove
instantaneous delivery of invalidation notifications to every process. Projected
informational balances can be stale, but financial mutation cannot trust them.

The Quint product directly imports the preceding account model and its actual
metered-source fixture. It adds local WAL/candidate/confirmation stages. Its
source-qualified flag represents the source-invalidation seam into the earlier
module; Lean stores that flag in the actual account state. The shared account's
second-reservation evidence remains the earlier explicit trusted fixture. No
arbitrary-many-provider or native consensus/storage product is claimed.

* Current source qualification and native acceptance

| Native gate | Required evidence before implementation acceptance |
|-------------+----------------------------------------------------|
| Atomic frame | Torn writes and process/power loss at header/body/checksum/commit boundary; reject incomplete or ambiguous frames |
| Flush/accept order | Candidate acknowledgment requires complete retained body; local flush alone changes no available balance |
| Protected decision | Lost commit reply and duplicate candidates produce one original application/reservation/hold/delta result |
| Log truncation | Remove/mutate local committed-prefix records, including equal-length wrong bodies; close and repair from current protected evidence |
| Missing authority body | Independent head exists but required record bodies are unavailable; no activation or empty-log replacement |
| Cross-store restore | Account ID/hold/balance/source/usage and local WAL at different positions; restore exact original result before mutation |
| Current final gate | Commit between observe/repair/install/activate and final use; stale confirmation or cached active flag cannot authorize funds |
| Old workers | Restored proposals, WAL descriptors/buffers and accepted candidate handles cannot bypass protected owner/source/head CAS |
| Unknown budgets | Missing final usage, source invalidation and unknown commit reply never release an original unknown hold |
| Checkpoint pruning | Before any future pruning, independently anchored complete checkpoint plus suffix must preserve all uniqueness/hold/binding facts |

Local proof closure is conditional on those native gates. No Gateway implementation,
real WAL parser, storage crash injection, quorum recovery, exhaustive exploration,
provider delivery, performance or recovery liveness acceptance is asserted.
