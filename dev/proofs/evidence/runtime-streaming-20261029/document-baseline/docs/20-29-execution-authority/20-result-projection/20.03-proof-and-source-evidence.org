* Actual source composition and new proof scope

=authority_projection= maps every authority mutation to an actual initialized
category-19 transition. Staging uses its stable-body stage, commit requires its
actual step, restart advances its fence, and source recovery uses its recovery
contract. Participant application, restored prefix images, observations and
activation leave authority untouched.

The projected category-19 run inherits origin/claim/index invariants, original
pending retention, spent-state retention and the shared exposure bound. Its
=source_projection= and =canonical_source_composition= then connect the actual
source path to category 18, with unrelated-origin stuttering and the previously
explicit per-origin/shared-account refinement obligation. No independent source
fixture is substituted for these Lean transition types.

=initialized_result_index= relates every result to its immutable original request
in the authority decision table. =fresh_decision_has_no_old_result= prevents another
commit under an already indexed transaction ID. =result_retained= preserves the
full typed result body. =initialized_positions_ordered= proves strict position
ordering over arbitrary finite logs. The exact application gate checks authoritative
lookup at the participant cursor, the next position, before-image equality and
current owner qualification. The duplicate-position lemma forbids a second apply.

The result image excludes pending staging and owner-visibility metadata, which have
separate recovery/fencing rules. It includes the actual source, identity indexes,
original decisions, nonce spent-state, exposure and execution revision. Native
canonical encoding must preserve this semantic footprint and separately bind the
full pending and owner metadata needed for complete authority recovery.

Recovery requires the owner to be retired/closed first. Its two explicit contracts
cover the original source recovery state and the complete new result-log wrapper
state. Qualifying only the old source state is insufficient to authenticate result
availability, prefix inheritance and participant fencing. A caller-supplied Boolean
cannot satisfy the native implementation of either contract.

The source/account participants use full typed images. The model permits restoring
a complete previously committed prefix while closed, then replaying exact results.
It does not model torn filesystem bytes as authenticated images. Invalid snapshots
must remain quarantined. Full native snapshot parsing, canonical hashes, fsync,
replicated prefix recovery and an implementation of atomic cursor/body publication
are qualification obligations. The result log itself cannot roll back in a valid run.

The extension has no refund, final-usage settlement or cancellation transition.
=unknown_exposure_retained= is monotonic risk retention, not a final invoice theorem.
The source relation used at commit must describe durable admission/consumption,
with transport tickets retained as data. It must exclude provider-offer/delivery
transitions. The generic source-path theorem does not derive that exclusion; the
concrete refinement must select actual prior admission constructors and separately
compose the broker/range execution gate. Applying a result never calls this source
relation again. The final broker still depends on the earlier durable operation/range queue protocol;
its native gate and application CAS must both serialize with owner retirement.

* Native acceptance obligations

Inject crashes before/after result-body durability, journal commit, response release,
each participant field write, cursor publication and acknowledgment. Restore source
and account from every relative prefix pair; malformed/torn bodies must never
qualify as complete images. Lose both commit and application responses, then query
and replay under a new owner. The original nonce, result, profile and unknown
exposure must remain unchanged.

Retain old-worker apply handles, queued mutations, SDK retries and late callbacks
through restart. Only current fenced CAS may publish a participant; historical
observations remain data. Verify that replay of a committed result never invokes
the provider, adds another reservation or releases unknown exposure. Verify the
queue admission check and owner/prefix change share a serialization boundary.

Missing result blobs, broken prefix inheritance or rolled-back fences block native
acceptance. The evidence here is local conditional formal/finite-model evidence;
no native storage engine, cryptographic commitment, provider transport, settlement,
remote exactly-once, liveness or performance result is asserted.
