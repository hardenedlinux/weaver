* Purpose

Weaver is a proposed unified gateway for governed service, agent, tool, and
model interactions. Zero Trust is a required starting design constraint:
no implicit authority follows from network location, process ownership,
language, or authenticated transport. Its architecture combines Scheme-driven
semantic composition with the networking, cloud-native, and systems capabilities of
the Go and Rust ecosystems. Language placement follows responsibility,
integration value, operational cost, and measured behavior.

This repository currently contains an architecture proposal, not a gateway
implementation. All runtime contracts below are proposed unless explicitly
identified as observations of a referenced repository.

The core design uses Cedar for explicit permission meaning, Scheme/POO for
Governance and composition, Go for cloud/protocol integration, and Rust for
the reference stateful coordinator and final broker. Quint and Lean examine
whether those boundaries preserve the declared Zero Trust contract. Read
[[file:docs/architecture/09-code-as-policy.org][the selection rationale]] and [[file:docs/architecture/diagrams/13-policy-to-execution.svg][the core policy-to-execution view]].

Read the system design and Zero Trust baseline first. The comparison distinguishes
inspected source behavior from requirements and hypotheses. The interface document is a
conceptual contract, not an implemented SDK or wire schema. The validation
document defines acceptance requirements; full runtime gates remain pending.
Focused formal results are recorded in the linked specification evidence.

The security review records fourteen design gaps and their required treatment.
Document revisions clarify those obligations; actual containment, stateful
commit, dispatch fencing, and protocol behavior remain unqualified.

The coordination proposal chooses one durable state domain and an ordered
consume-then-commit protocol, with conservative no-redispatch recovery for
unknown non-idempotent sends. The ignored =.data/agentgateway= checkout is a
fixed source reference, not a runtime dependency.

The source-admission refinement keeps undecided preflight inert and specifies
separate runtime admission, authoritative ledger command resolution, and three
distinct fencing boundaries. Process restart and timeout cannot reopen a claim
or recreate permission from serialized receipts. The cross-review additionally
separates submission, emitter closure, external outcome, settlement and response
release. Code as Policy is a mandatory Zero Trust requirement; existing Cedar
source is reused without claiming the remaining runtime bridge is implemented.

Quint and Lean are required architecture components, with cedar-poo-spec as a
critical semantic dependency. The first [[file:specs/quint/LogicalMessageAuthority.qnt][executable Quint model]] and
[[file:specs/lean/LogicalMessageAuthority.lean][checked Lean proof]] now cover a focused logical-message/issuance/evidence
machine. [[file:specs/README.org][Formal artifacts, theorem correspondence and validation receipts]] distinguish
this checked abstract safety from pending source refinement, full FM coverage
and runtime qualification. Different inspected Lean/Cedar declarations still
require one selected owner-integration baseline.
This is internal consistency and native qualification, not backward compatibility.

* Current scope

- Architecture and design documentation only, written in English Org.
- D2 diagram sources, a shared presentation theme, local brand assets and generated SVG/overview PNG previews accompany the Org documents.
- No gateway implementation, generated schemas, dependencies, benchmarks, or deployment changes.
- Scoped owner builds, native checks and retained failures are documented; no complete Weaver or deployed acceptance is claimed.
- Existing environment configuration is outside this documentation change.


The [[file:docs/architecture/17-shared-identity-budget-proof.org][cross-message extension]] adds actual Quint/Lean artifacts for canonical
alias resolution, two logical messages, one weighted budget and shared history.
[[file:specs/README.org][The formal guide]] keeps source premises, proof correspondence, bounded
simulation and remaining runtime qualification separate.


The [[file:docs/architecture/18-finite-domains-and-migration.org][finite-domain extension]] generalizes the checked ledger to arbitrary finite
message sets and independent overlapping budget/history accounts. Domain and
process lifecycle changes preserve canonical obligations; old tickets and
claimed executors cannot be silently refreshed. [[file:specs/README.org][Proofs, model commands and
scope limits]] remain explicit alongside runtime qualification requirements.


[[file:docs/architecture/19-anchor-recovery-and-egress-contract.org][The anchor/recovery/egress contract]] adds checked conditional journal and
range proofs, rollback/lost-reply/buffer counterexamples, and an explicit physical
acceptance register. Old accepted buffers may drain after a logical cut;
receiver business fencing does not retract disclosure. Physical qualification
remains separate from those formal results.


The [[file:docs/architecture/20-composed-journal-transport-lifecycle.org][composed lifecycle]] connects the empty finite ledger, exact migration seal,
immutable journal decision, complete recovery and actual transport-owner
admission in one reachable Lean product. Quint covers phase races and lost
replies across owner restart. Durable range records retain uncertainty and
prevent replay; actual storage/driver qualification remains pending.


The [[file:docs/architecture/21-finite-stream-manifest-proof.org][finite stream manifest extension]] now supports arbitrary finite range counts
under the original complete-message claim. Checked Lean composition covers
immutable partitions, affine partial-offer frontiers, unique stream tails and
shared escrow coverage. Quint retains prefix-rewind, restart replay, overlap
and budget/history bypass controls. Physical ownership qualification remains
separate; no gateway implementation or dependency pin changes.


The [[file:docs/architecture/22-driver-completion-recovery.org][driver completion and recovery extension]] separates possible-offer frontier,
original-driver relinquishment and final usage. Checked Quint/Lean artifacts
retain canonical completion across lost replies and forbid tail adoption after
driver restart. Physical writer isolation and durable transaction qualification
remain explicit acceptance obligations.


The [[file:docs/architecture/23-writer-isolation-settlement-closure.org][writer isolation and settlement extension]] separates immutable evidence,
canonical terminal decisions, local publication and financial materialization.
Checked Quint/Lean artifacts retain original ownership across cross-store reply
loss and join final usage to published terminal coverage and original shared
reservations. Physical writer/storage/provider qualification remains pending.


[[file:docs/architecture/24-settlement-anchor-recovery.org][The account application and anchor recovery extension]] joins original
settlement intents, protected gate consumption, atomic application receipts and
independent confirmations. Checked models reject mixed restored images and retain
unknown reservations; rollback of the protected gate itself remains an explicit
failed premise requiring physical qualification.


[[file:docs/architecture/25-gate-consumption-persistence.org][The gate consumption persistence refinement]] permits local journal loss while
preserving independent seal/issuance/burn tombstones. Unknown burns block full
recovery and retain original reservations; authentic late original receipts close
the chain without replay. [[file:specs/evidence/gate-consumption-persistence-2026-10-19.org][The formal receipt]] keeps native qualification distinct.


[[file:docs/architecture/26-anchor-commit-broker-fencing.org][The anchor commit and broker handover refinement]] separates durable committed
history from actual writer authority. Election leaves an explicit old-broker
window until physical isolation; qualified prefix/fence activation preserves the
same original operation and unknown reservation. [[file:specs/evidence/anchor-broker-commit-2026-10-19.org][The executable receipt]] keeps
store-owner and native premises explicit.


[[file:docs/architecture/27-anchor-configuration-prefix-inheritance.org][The configuration and prefix-inheritance refinement]] extends the root model to
serialized old/joint/new membership. Joint transitions require both quorums and
complete deciding-image inheritance; configuration publication does not isolate
old broker handles or create fresh application authority. [[file:specs/evidence/anchor-reconfiguration-2026-10-19.org][The receipt]] separates
conditional formal results from native consensus and writer qualification.


[[file:docs/architecture/28-quorum-durable-promises-prefix-recovery.org][The quorum durable-promise refinement]] separates restored replicas from protected
non-equivocating witnesses and exclusive signer qualification. Its conservative
sticky-prefix profile closes the shared-witness rollback gap while retaining the
original execution and budget model. [[file:specs/evidence/quorum-durable-promises-2026-10-19.org][The receipt]] records executable counterexamples,
conditional Lean composition and the remaining native trust boundary.
