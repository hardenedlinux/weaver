#+LANGUAGE: en

* Engine and project extensions

=@deterministic-engineering/render= owns the rendering engine, D2 declaration
reader, composable visual themes, font resources, drawing utilities and image
export. Weaver supplies captured Org/SysML/D2 inputs, domain-specific compositions,
local assets, output publication and graph-binding verification. It does not
maintain a second layout engine, font-outline implementation or generic card
renderer.

Project composers answer different questions: the gateway responsibility map
focuses on Scheme/Go/Rust allocation; its relationship matrix aggregates declared
owner relationships; execution/proof correspondence compares three obligation
lanes. Other views use the library's standard D2 model rendering. Domain
composition and visual theme are independent choices.

Each D2 view declares its presentation Question, copy, purpose, layout, ordered
theme layers and variants through the library's existing =data.figure= contract.
These are design-view questions, not issued governance Questions or accepted
review/authorization evidence. =Project.sysml= and the existing Go OpenSysML
checks retain their model-ownership role.

* Local library consumption

GitHub publication is unnecessary. The development dependency is a local package
archive at =.data/render-library/deterministic-engineering-render-1.0.0.tgz=.
The archive is ignored; its dependency integrity is recorded in =bun.lock=.
From the library package directory, use its standard package command:

#+begin_src text
bun pm pack --destination <weaver>/.data/render-library
#+end_src

From =dev/d2=, install the captured development dependencies and browser:

#+begin_src text
bun install --frozen-lockfile
bunx playwright install chromium
#+end_src

A frozen installation requires the captured package bytes. An updated local
library requires an intentional development lockfile update. Existing Rust, Go,
Scheme and proof dependency pins are independent and remain unchanged.

* Rendering and artifacts

From the repository root:

#+begin_src text
go -C go run ./cmd/weaver-dev check-diagrams
go -C go run ./cmd/weaver-dev render-diagrams
#+end_src

A focused selection can be rendered from =dev/d2=:

#+begin_src text
bun run render --view docs/architecture/diagrams/01-system-boundaries.d2
#+end_src

The default entrypoint uses the library for every selected view. The host owns
one reusable browser and a separately recoverable D2 compilation scope. Image
jobs use the host CPU count; active contexts drain before browser shutdown.
There is no HTTP service. Browser subprocess memory is outside the earlier
Bun-only RSS measurement; do not reuse that measurement as a process-tree bound.

The library produces Question-led HTML and PNG. Full D2 SVG remains a technical
model reference. Selected project compositions publish adjacent PNG previews and
declared theme variants. Cached HTML, image receipts and raw diagnostics belong
under =.cache/d2= or temporary storage.

* Reading and fidelity contract

Main figures use readable labels, meaningful icons and deliberate grouping.
Necessary explanations belong beside their subjects or constraints. Detailed
premises, source references and qualification notes stay in Org rather than tiny
footer text. A responsibility view, relationship matrix, message sequence and
proof view need different spatial organizations; a theme alone does not choose
that organization.

The responsibility map aligns the three owner headings and content rows. Its
contract strip derives the admitted closure, admitted publication and source
guards from actual D2 edges, including direction. These are semantic handoffs,
not a claim that every edge is a network connection. The full relationship
matrix and technical SVG retain the more detailed model. The bottom Zero Trust
band states shared constraints at a readable size rather than carrying hidden
explanatory footnotes.

The host graph gate checks one declaration, unique nonempty identities, node/edge
coverage and bound endpoints in the full model SVG. Question-led projections may
aggregate those relationships explicitly, as the owner matrix does. Compilation
and project mapping remain trust premises. Export checks do not prove runtime
Policy enforcement or replace Quint/Lean, geometry review and human inspection.
