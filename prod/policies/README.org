#+TITLE: Production Policy Contracts
#+LANGUAGE: en

* Runtime ownership

The [[file:../../Project.sysml][Project ProductionAssetBoundary]] governs this
directory. Runtime-consumed Cedar policies, schemas and manifests are production
assets. Production code/build/startup inputs cannot import, embed or load tracked
=dev/= files, nor resolve a =prod/= alias back into development. A generated
candidate is validated and promoted into a declared production asset before
deployment; copying a proof output does not grant publication authority.

Development proof sources, solver/replay diagnostics and test runners remain
development inputs. Tests may inspect these production assets; the production
dependency direction cannot reverse. Mutable epoch/revocation/consumption data
belongs to the configured durable authority store, not a versioned asset file.
See [[file:../../docs/50-59-research-program/59-provider-rpc/59.56-runtime-assets-and-authority-floor.org][the runtime boundary and authority-floor contract]].

* Contract owner

=provider/schema.json= and =streaming/schema.json= define the Cedar action,
entity and context contracts used by the Rust authority. They are production
assets. Scheme preflight, Go integration tests and Rust tests consume these
same files rather than maintaining development copies of the schema.

=provider/profile.json= and =provider/profile.yaml= encode the same reference
provider profile contract. A source owner must explicitly select and publish a
profile with the original task; these files do not automatically grant authority.
Production policies remain explicit source-owned publication inputs and must
validate against their selected schema. Rust rechecks current Cedar decisions
at final execution and release.

* Verification boundary

=provider/provider.cedar= and =streaming/stream.cedar= contain the reference
policies. =provider/request-cases.json= contains their associated validation
vectors. Policy, schema, profile and case assets share this production owner.
Scheme suites live in =t/*-test.ss=; Go/Rust integration and PBT consume these
same assets. Quint and Lean remain under =dev/proofs/= with
explicit refinement premises and the existing cedar-poo-spec dependency.
Runtime logs and isolated builds are temporary and cleaned. Compact latest
results overwrite fixed Git-ignored =.cache/verification/= slots.

The =prod/= and =dev/= directories express asset and tooling ownership. They
do not classify feature maturity or replace explicit deployment admission.
