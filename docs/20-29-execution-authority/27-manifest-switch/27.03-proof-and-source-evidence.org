* Formal construction and composition

=Available= requires the exact manifest body, every referenced segment and any
selected checkpoint body to be present. =Safe= adds exact replay equivalence and
agreement with the actual parent checkpoint/suffix representation. Segment and
manifest durability are explicit Owner predicates. Native root durability is
=Owner.switchDurable=; authentication is =Owner.rootAuthentic=.

=Step.switchRoot= requires actual parent checkpoint transition evidence, current
selected publication and confirmation, durable checkpoint, complete replacement,
parent match, current owner, policy and durable root switch. It does not delete
old objects. The result clears the observation and closes the parent WAL gate.
=erase= requires current observation, owner, generation and non-reachability;
it filters one immutable ID. Crash clears observations without rolling back the
protected logical state or the durable root. Object/manifest staging uses fresh
allocation identities. Each arbitrary finite prefix remains reconstructible by
=safe_step= and =recovery_copy_retained= from an explicitly supplied safe initial
representation. This is not an unconditional theorem that every native startup
image is trustworthy.

=logical_projection= maps each step to an actual checkpoint run; storage-only
steps stutter, crash is actual lost-response closure, and authority/activation use
actual parent actions. =actual_checkpoint_composition= attaches a supplied actual
initialized parent prefix. Uniqueness and unknown-budget results then use the
existing checkpoint/WAL/account/source proofs, not duplicate counters.

Quint storage actions perform an authenticated pure financial-head read before
the storage mutation because the imported parent has no public generic hold action.
That read refines a permitted Lean =authority= step, followed by the storage step.
It cannot fabricate a provider completion or usage receipt. The independent ITF
decoder verifies unchanged actual provider execution state throughout these phases.
The control fixture contains one original committed record; a second initializer
contains a later committed suffix. Lean permits arbitrary finite segment lists and
runs but freezes the represented WAL sequence during a cut, as specified in 27.01.

=lastDeleteAuthorized= is a ghost negative-test monitor, not a production permit
or anti-rollback authority. Losing a readback is a conservative protocol violation
if a broken variant deletes without it, even when that particular obsolete deletion
happens not to destroy the selected path. The decoder distinguishes this guard
violation from actual missing-copy and replay violations.

* Native acceptance obligations

| Gate | Required executable evidence |
|------+------------------------------|
| Object-before-root ordering | Power loss at every write/fsync/publish boundary; old or complete new path survives; truncated/torn body never qualifies |
| Root switch | Lose response before/after durable parent CAS, duplicate same operation, competing parent and generation exhaustion; exact original result or fail closed |
| Deletion serialization | Pause old worker after validation, change owner/root, resume actual unlink; new reachable objects survive or takeover waits for the old critical section |
| Partial deletion | Crash before/after each obsolete unlink and directory persistence, including already-missing files; repeat idempotently with no balance delta |
| ABA and shared suffix | Reuse pathname/inode number, stale descriptor and shared segment; immutable identity and current reachability reject unsafe deletion |
| Independent rollback | Restore root, object store and account snapshots inconsistently; qualify against retained publication/financial anchors or remain closed |
| Restart and late result | Deliver old switch/deletion acknowledgment to a new owner; it cannot install a stale root or act as reusable permission |
| Complete financial recovery | Preserve application IDs, reservation tombstones, unknown holds, namespaces/defaults, original profile/claim/history and ordered committed suffix |
| Pending suffix and append | Race accepted candidate commit and append-generation capture; pending frames stay inert and no later frame is silently dropped |
| Final use | Restored projection still crosses current source/Policy/history/owner and broker/executor gates; storage completion never triggers external send |

The typed model assumes immutable complete records and qualified native IO.
It does not prove torn-byte parsing, codec/hash security, independent anchor
consensus, concurrent reader lease recovery, general append rollover, archive
pruning, provider exactly-once delivery, bounded recovery progress or performance.
