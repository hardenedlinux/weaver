* Actual product and composition proof

The combined state contains the actual category-21 admission state and the actual
=LogicalRangeRecovery.State= for one immutable admitted operation. =queue_projection=
maps background changes to actual category-21 transitions and executor actions to
stutters. It retains original admission, canonical slot and source exposure proofs.

=range_projection= maps lane fencing, no-offer progress and final invocation to
actual existing range transitions. Other actions stutter. The no-offer guard on
range progress excludes invoke; =invocation_requires_current_gate= proves that any
change in the invocation counter must come from the dedicated final offer action
with its current gate, original burn, unsubmitted state and effective Policy.

The initialized range invariant gives =offer_at_most_once=. The existing checked
=initialized_data_path_refines_queue= then constructs an actual initialized
=BrokerConsumptionQueue.Run= for the projected original interval. Its unknown-hold
theorem supplies =unknown_retains_broker_hold=. This closes the earlier conditional
suffix gap with an actual composed range history, rather than a parallel counter.

The prior range-to-broker projection erases some permission generations and mirrors
source consumption/acceptance as an abstraction. That abstract accepted state is
not an execution grant. Every new invocation in this product separately requires
actual queued operation and canonical slot lookup, dequeue, execution qualification,
current source/account join, current owner and range permit, and current offer Policy.
Native authenticity must not be inferred from the erased broker owner.

* Gate, phase and recovery contracts

An offer ticket binds the complete current admission view and held range permit.
It compares source image/prefix, queue revision, Policy/history generation, global
owner, lane owner, lane generation and range revision at final use. A persistent
source-owner change clears executor qualification. Source recovery alone cannot
qualify the lane; a whole-executor recovery predicate is required before owner
alignment and new observation.

The =reserveRecordedDispatch= and =offerRecordedRange= predicates are distinct and
both receive the complete executor state. The current offer predicate therefore
has access to source, lane, burn, submitted marker and execution history. Matching
an old dequeue request or an old enqueue allow receipt is insufficient.

The background validity contract also receives the complete execution state. It
must prevent no-execution/terminal/refund conclusions from zero admission-plane
counters while permitting legitimate governance updates. Source-only existing
owner proofs cannot be reused as authoritative execution absence certificates.
The outer source-exposure theorem proves monotonic risk retention; a complete
native source/execution/settlement/account product remains a separate obligation.

The original burn and submitted marker are monotonic. There is no constructor that
clears either, no invocation-count reset and no new tail or manifest constructor.
Partial progress and timeout use the actual range model's data/stutter behavior.
An authentic exact original full receipt may update the range after handover; it
does not recreate a permit, release source exposure or clear the original slot.

The model has one selected source-admitted possible-offer interval. Admission may
contain arbitrary other operations, and runs/logs are arbitrary finite paths.
Pointwise lifting to already admitted disjoint ranges still needs the earlier
manifest/non-overlap and shared-account products. No automatic partial-tail resume,
uncertain-burn reclamation, settlement or recovery liveness is asserted here.

* Native linearization and evidence limits

Logical final offer is the last serialized possible-I/O handoff, not producer
queueing or an editable callback. Durable marker release must be affine, and every
real provider invocation must refine one such original event. A marker may be
conservative when a crash prevents actual I/O. The native mapping must establish
that one marker cannot release two real callbacks; models do not instrument an
unwritten transport implementation.

Policy/owner effectiveness is ordered at this final boundary. A cut before handoff
blocks; an earlier irreversible handoff remains an original in-flight operation.
The proof does not promise zero later wall-clock wire bytes from kernel or remote
buffers. Old mutable SDK buffers and direct network handles cannot be admitted as
an alternate execution path. Exclusive writer and non-rollback prefix qualification
remain explicit native premises, with fail-closed behavior when unknown.

Receipt validity includes original-call attribution, consistency, actual complete
coverage and current parsing/codec interpretation. The fixture's partial receipt
is incomplete nonterminal evidence. A terminal short write cannot be upgraded to
full completion by a forged or contradictory byte count. Definitive short-write
and safe unoffered-tail evidence belong to the earlier qualified frontier protocol;
this extension does not synthesize them.

* Native acceptance

Pause after dequeue, offer observation and durable burn; publish Policy/history and
move ownership before resuming. Verify actual last handoff rejects stale work and
fresh tickets still obey original scope and effective denial. Source recovery alone
must not enable the executor. Validate full dispatch-prefix recovery and current
range-owner mapping with old callbacks and buffers retained.

Crash before/after the submitted marker and possible transport handoff. Lose both
responses, return short/partial writes, restart and reconnect. Verify zero replay,
no new tail, immutable original invocation and full unresolved reservation. Test
late authentic full evidence, contradictory terminal totals, repeated receipts and
forged completion. Check original source/queue/dispatch identity across every store.

Native acceptance still requires durable/atomic protocol evidence, non-rollback
lineage, semantic/codec correctness, final-writer exclusivity, receipt consistency
and actual I/O instrumentation. No implementation, benchmark, liveness or remote
exactly-once claim follows from these local results.
