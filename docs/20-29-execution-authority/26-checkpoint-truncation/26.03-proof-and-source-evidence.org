* Physical representation and actual composition

The product stores the actual =LlmWalActivation.State=, immutable publication history,
complete checkpoint bodies, a physical local checkpoint/suffix representation and
a publication observation. =Valid= requires exact complete checkpoint image equality
to the covered prefix's reference result, covered position agreement and actual
protected financial-prefix membership.

=logical_projection= maps each checkpoint action to actual WAL runs. Publication
and truncation close the prior activation/readback; physical restore becomes a WAL
restore; repair becomes actual WAL repair; activation uses an actual prior WAL step.
Checkpoint body validation and publication readback include authenticated pure
financial-head observations; they cannot manufacture provider completion receipts.
Financial progress still follows the actual earlier WAL/account commit protocol.
=actual_wal_composition= joins initialized actual runs through arbitrary finite
checkpoint paths. It preserves original account uniqueness and source budget facts.

=truncation_preserves_replay= states the representation law and the actual reduction
in physical suffix record count. =expanded= combines a proof witness of the covered
prefix with the physical suffix. The witness is ghost/reference history, not a
native claim that deleted frames remain on disk or should be serialized inside the
checkpoint. Native equivalence must be authenticated by the complete persisted
image and qualified coverage lineage, not by inventing witness bytes at recovery.

=initialized_safe= proves complete published images and current physical/publication
qualification whenever active. =old_checkpoint_snapshot_stays_closed= excludes an
old selected checkpoint even if its expanded logical WAL happens to be complete.
The earlier WAL activation theorem independently rejects a missing committed suffix
or stale financial confirmation. Both gates are needed.

=publication_floor_monotone= is a transition theorem: no guarded restore or lost
response decreases the protected publication floor. =checkpoint_ids_unique= proves
that any two published entries with the same ID have the same complete checkpoint
body. =published_checkpoint_retained= preserves original publications over restart
and response loss. The body registry may contain speculative blobs; the exact
published body is the authoritative identity resolution.

The account authority, canonical source registry and protected original outcome
archive are not physically pruned by this model. They remain the recovery reference.
The new logical equivalence does not prove safe deletion of those independent
histories or expiry of application/reservation deduplication entries.

* Commit boundary and pending suffix

The suffix may contain an accepted but uncommitted account candidate. Presence of
its frame or valid after-image does not mean its financial effect occurred.
=pendingTailIsNotReplayedAsFinancialDeltaTest= reaches that state with an active
projection while the original hold remains intact. The financial head, not the
physical suffix length, limits replay.

=lateCandidateAfterTrimReplaysThroughSuffixTest= retains the independent candidate,
trims only the earlier checkpoint prefix, lets the candidate commit through the
actual account gate, and replays to the new protected head. Its checkpoint still
contains the historical unconsumed hold; the current account correctly reflects
the later original settlement once. =trimCannotDiscardUncommittedTailTest= rejects
silently deleting that suffix in the selected truncation operation.

Unsafe constructors are excluded from =step=. Their controls deliberately expect
the named invariant to fail. The independent ITF decoder (retired Python driver) checks original actual
queue/spent/exposure history, checkpoint image fields, physical suffix, publication
parents/floors, owner stamps and qualified financial state. It also verifies that
checkpoint actions leave the actual provider execution state unchanged after the
checkpoint fixture has initialized.

The =floorSeen= variable is an independent test monitor of prior publication floor.
It detects the deliberately broken co-rollback transition; it is not a native source
of authority and cannot make a co-restored system authenticate itself. Native
non-rollback publication/fence qualification remains a separate premise. The
unknownHold control concerns an unconsumed fixture hold; actual unknown source
usage is covered by the inherited guarded account controls and Lean composition.

* Implementation acceptance and evidence boundary

[[file:../../../dev/proofs/evidence/llm-checkpoint-truncation/working-source-check.json][Live source hashes]] separate current working files from pinned references.
Eighteen match; P17 differs only in two control-plane import paths, recorded in
[[file:../../../dev/proofs/evidence/llm-checkpoint-truncation/P17-working-diff.patch][the captured working diff]]. That textual comparison does not establish runtime/ABI
equivalence of the new import targets.

| Native gate | Required executable evidence before implementation acceptance |
|-------------+---------------------------------------------------------------|
| Complete body | Remove one application, reservation, unknown hold, namespace/default or source binding; reject before publication |
| Durable body retention | Crash during checkpoint write/upload and lose all local WAL copies; only an authenticated complete retained body permits recovery |
| Atomic publication | Lose response before/after parent CAS; read back one exact checkpoint ID/body and monotonic floor |
| Publication races | Concurrent parents, duplicate IDs/different bodies, checked counter exhaustion/overflow, financial commit during capture and late old publication replies |
| Atomic local representation | Crash across manifest install, fsync and physical prefix deletion; recover a verified before/after representation or remain closed |
| Snapshot rollback | Restore old checkpoint/account/WAL snapshots independently, including old checkpoint plus complete WAL; no floor downgrade or empty genesis fallback |
| Suffix commit boundary | Preserve uncommitted frames as pending; replay only independently committed suffix entries; late candidate settles once |
| Current fence | Old worker with fresh publication reply or truncate descriptor cannot bypass current owner/selection/floor checks |
| Final activation/use | Financial and checkpoint confirmations must both be current; cached active bits cannot authorize a restored balance |
| Independent authority | Publication floor, owner/source stamps, canonical registry and original outcome archive survive local rollback or qualification stays closed |

The physical suffix is modeled as complete typed records. Torn bytes, parser/default
semantics, hash/codec authenticity, object availability, atomic filesystem operations
and distributed publication durability are native premises. The protected financial
journal is retained; safe deletion of that authority, archive pruning, dedup expiry,
provider delivery, performance and bounded recovery liveness are not established.
