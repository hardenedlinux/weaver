* Product state, safety and actual refinement

=State.logical= is the actual =LlmCheckpointTruncation.State=. Segments and immutable
manifests use the category 27 types. The physical representation consists of root
segments, closed cut segments and live-generation segments; =replay= must equal
the actual logical WAL, and checkpoint/suffix must agree with the actual parent.
Every root/candidate checkpoint body remains present. Every referenced segment
is present and durable; the current immutable root is durable.

=Aligned= ties the unresolved cut to its captured records, original root,
root generation and successor append generation. =Candidate= requires a staged
replacement to replay exactly that captured prefix. Candidate staging cannot
turn an uncommitted frame's after-image into a published financial checkpoint.

=Step.append= invokes the actual WAL =flush= premises: prepared original proposal,
actual account =Ready=, current journal equality and durable exact frame.
=Owner.appendDurable= separately requires durable admission of that frame and
its frontier reference; segment bytes alone do not satisfy this premise. It adds
a fresh immutable segment and advances the frontier. Its parent projection is
the actual checkpoint =advance= of that actual =flush=, not arbitrary WAL restore.
The complete initial physical representation is an explicit premise of the
projection/composition theorem.

=sealCut= freezes all admitted live segments, increments the admission generation
and persists its original cut intent. =switchRoot= requires actual parent transition
evidence, selected publication and its confirmation, authenticated durable
checkpoint, durable immutable candidate, exact current descriptor and durable
root/append-descriptor decision. It carries =live= unchanged. =erase= checks the
union of all current and pending references at actual deletion. =authority= admits
actual parent transitions preserving represented WAL/checkpoint/suffix and bodies,
including late account commitment, owner rotation and financial recovery reads.

=logical_projection= and =actual_checkpoint_composition= compose into the actual
checkpoint/WAL/account/source chain. Original reservation uniqueness and unknown
holds are inherited through those real runs. This is not a claim that category
27's fixed-WAL =Run= already permits concurrent append. This extension replaces
that fixed-representation contract; it reuses category 27 immutable types and
safe-delete obligations and establishes its own preservation theorem.

Quint storage-only operations use an authenticated pure financial-head read,
which maps to an actual parent authority step followed by the corresponding
storage transition. No operation fabricates provider completion or metering.
The independent decoder checks unchanged actual provider execution state from
initialization through every mutation trace.

The native typed state requires durable admission descriptors, root binding,
immutable content identity and real effect-time serialization. Complete typed
objects do not prove torn-byte handling, hashing, CAS durability or filesystem
ordering. Root crash durability also does not replace independently governed recovery
qualification after snapshot rollback. Financial/checkpoint anchors alone may
remain unchanged while a pending append frontier is lost. Admission/cut minimum
publication in the retained original pending-intent/control log is a required
native extension, as specified in 28.01; it is represented by Owner premises,
not proved by preserving an in-memory counter.

* Acceptance evidence and proof boundary

| Native gate | Required executable evidence |
|-------------+------------------------------|
| Append admission ordering | Crash before/after body persistence, descriptor CAS and response; no accepted frontier without its durable body |
| Append idempotence | Lose admission response and retry the same operation; resolve one exact admitted frame or retain original pending intent |
| Seal/open decision | Crash between sealing old generation and opening successor; recover exactly one appendable generation without default reset |
| Queued old writer | Pause old worker/FD callback before actual admission, advance cut/owner, resume; reject retired descriptor despite durable staged bytes |
| Concurrent cut | Admit a frame immediately before/after cut linearization; every acknowledged frame appears exactly once in captured or live ordered suffix |
| Switch frontier race | Append between join validation and switch CAS; retry current handoff bundle or carry current live descriptor, never lose a tail |
| Late financial commit | Commit accepted original frame before/after switch and lose response; original application/reservation settles once and replay follows financial head |
| Uncommitted replay | Preserve pending suffix without advancing financial head, releasing its hold or inferring no-execution |
| GC effect race | Resume old deletion with current live/shared/candidate objects; actual unlink checks the complete reference union and current fence |
| Cross-store rollback | Roll back admitted/cut frontier even when financial head and checkpoint are unchanged; independently published admission minimum rejects the snapshot or keeps recovery closed |
| Fenced proposal continuation | Reauthorize current-owner continuation with original application/reservation and retain unknown hold; no timeout-based abandonment |
| Counters and namespace | Reject exhausted generation/frontier/cut/allocation counters, pathname ABA and incomplete map/default/source identity recovery |

The Lean result covers arbitrary finite segment lists and guarded runs. Its
actual per-account flush is serial with one uncommitted settlement frame; it does
not qualify a speculative multi-candidate before-image pipeline. The Quint fixture
contains one original committed record and one pending/later committed record,
not an arbitrary-account product or exhaustive fault-space exploration. Durable
IO, admission deduplication, anchor consensus, native codecs, independent reader
lease recovery, pending-owner continuation liveness, provider delivery and
performance remain explicit implementation/acceptance boundaries.
