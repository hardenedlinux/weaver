* Concrete product and initialized composition

=State.logical= is the actual =LlmAppendHandoff.State=. The independent protected
log stores exact original proposals and complete storage recovery images. Local
projection, copied objects/checkpoints, current-head observation, historical
resolved result and active diagnostic state are separate fields. =Image= captures
root, closed/live tail, original allocation identity, generations/frontier, cut,
candidate and current owner/source generation. It contains no financial authority
projection that may replace account balances.

=propose= retains original attempts under immutable intent binding. =commit= checks
current qualification, exact parent/before-image, current worker, original key
freshness, actual handoff step, canonical intent, durable body, Policy and durable
independent publication. The actual handoff step supplies the real admitted frame
or cut semantics; account authority and financial journal must remain unchanged.
=financial= permits actual handoff transitions whose storage image stays unchanged,
including preparation, current reads, candidate submission and a real later account
commit. It closes local activation but does not invent another floor record.

=resolve= reports one historical determining record without confirming the current
head. =query= authenticates the current head and worker. =restore= changes only
local metadata/copies and closes prior observations. =fetch= authenticates complete
archive retrieval. =project= and =activate= require current qualification and full
body coverage. Restoration of a complete old WAL cannot replace the current image.
A root image with a missing live/closed tail fails =Complete=.

=logical_projection= maps every publication/financial step to actual handoff runs;
metadata recovery stutters. =actual_handoff_composition= joins a supplied initialized
handoff prefix. The original account uniqueness/unknown-hold statements use the
actual checkpoint/WAL/account/source chain through that composition. The seed
record assumes an authenticated original namespace and valid base; it does not
prove bootstrap or permit a fresh empty namespace after restart.

=committed_prefix_retained= preserves the protected log; =pending_intent_retained=
preserves original attempts, including conflicting-parent attempts after safe
reauthorization. =committed_operation_unique= says equal original operation IDs
have equal determining records. A duplicate network message reporting that same
record is not another financial application. The guarded commit rejects a second
publication of the key entirely. The conflict mutation deliberately changes the
result body for that same key; merely duplicating an identical record would not
violate this particular theorem.

Quint's =capture= uses the full bounded storage image and current worker. Its source
generation is fixed in this fixture; Lean captures the actual governed source
generation. Financial head changes remain separate from storage image equality.
Storage-only Quint actions include an authenticated pure financial read and an
explicit imported =h'=h= hold. They refine actual image-preserving handoff steps
followed by the corresponding metadata action; they cannot create provider or
usage receipts. The decoder verifies unchanged actual provider execution state.

* Implementation acceptance and evidence boundary

| Gate | Required executable evidence |
|------+------------------------------|
| Prepare/archive pin | Crash before/after object persistence and retention publication; only fully retrievable exact determining bodies may commit |
| Independent commit | Lose response before/after parent CAS; one exact original result survives qualified leader/configuration recovery |
| Concurrent attempts | Competing same-parent attempts, canonical-key conflicts and reauthorization preserve original intent/pending bodies without double admission |
| Current receipt | Deliver an old valid original-result or head response after a later cut/fence; actual use rejects it as current authority |
| Cross-store rollback | Restore local descriptor, manifest, segment and account projections independently while financial head/checkpoint stay unchanged; floor forces exact pending-tail reconstruction or closure |
| Archive failure | Lose the local unique tail and fetch from qualified retained archive; missing/corrupt/conflicting archive content keeps closed and retains hold |
| Owner takeover | Pause an old worker after readback, publish a fence, resume commit/project/activate/unlink; actual owner rejects the old descriptor |
| Publication-only effect | Instrument control commit; no account delta, provider call, grant reconsumption or financial replay occurs |
| Recovery join | Race financial/source change between validation and publication; actual source-admission bridge must revalidate/serialize the original handoff. Rebuild cannot restore financial authority or bypass final broker/executor gates |
| Qualified independence | Roll back replicas and change membership/leader; recover full determining prefix and retention obligations or refuse authority; no fresh empty namespace |
| Exhaustion/encoding | Reject bounded counter overflow, incomplete maps/defaults, identity substitution, body/hash mismatch and namespace reuse |

The model assumes a single qualified durable independent prefix, authentic current
reads and retained determining bodies; it does not prove a new consensus, quorum
or physical device implementation. Prior logical prefix/fencing contracts remain
requirements. The handoff layer retains its one unresolved cut and one uncommitted
settlement frame per account lane. Native codec/IO qualification, protected-log
or archive pruning, arbitrary-account products, pending-owner continuation
liveness, provider exactly-once delivery and performance remain outside this result.
