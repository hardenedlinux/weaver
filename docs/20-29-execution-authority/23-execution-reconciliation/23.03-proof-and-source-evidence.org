* Actual composition and proof limits

=Step= contains the actual =LlmExecutorOffer.State= and actual
=LlmAttemptLedger.State=. Source transitions carry an actual imported source
=Step= proof. A source application must change an originally unset terminal to the
chosen kind and align the selected call count with negative or executed evidence.
Usage application requires an originally absent usage and an actual source step.
Ordinary source progress preserves selected terminal/usage, and any selected call
change additionally requires dispatch possible-execution evidence.

=source_projection= constructs the actual source suffix.
=source_composition= extends an initialized source run, rather than pretending that
a source ledger fabricated at recovery has an initialized invariant.
=actual_source_capacity= and =actual_source_unknown_prevents_close= reuse the actual
source budget and close theorems on this composed run.

=execution_projection= constructs an arbitrary finite execution path.
=actual_executor_composition= maps that path to the actual category-22 executor
=Step= relation using an explicit mapping and an initialized executor prefix.
Consequently its original queue/range/broker results can be reused. The mapping
must be supplied by the implementation refinement; an arbitrary relation =D= is
not automatically an authorized executor transition.

=absence_after_seal= proves that a closed, absent execution suffix stays absent:
any later execution step preserves the original burn, submitted marker and call
count. Closing cannot be inferred solely from a source lease. The native
=closedPrefix= premise must establish exclusive complete-prefix closure with the
final broker, including every callback still capable of making a possible offer.

The product proves one immutable decision and one account application for a
selected original attempt/reservation. The fixed attempt, original binding and
initialized source prefix are parameters. Full original registry identity is
inherited under native binding qualification, not proved by a fresh numeric key.
Financial release is a logical account CAS over that one reserved bound; native
atomic coupling of application identity and balance delta remains unimplemented.
The source model's =allocated= stays monotonic; no refund is smuggled into it.

Quint imports the actual executor module and composes its variables with a
reconciliation state. Its source/application records abstract source terminal and
metering rather than execute the Lean attempt relation. It additionally models
stale dispatch/source/account views and tests exact recovery joins. Lean's recovery
predicate receives the whole product state, while restart preserves authoritative
records. Neither model proves that an arbitrary physical snapshot is authentic.

* Implementation acceptance gates

| Gate | Required executable native evidence before implementation acceptance |
|------+--------------------------------------------------------------------|
| Closed prefix | Race final offer with close; show one serialized outcome and no old queued closure can offer afterward |
| Conservative absence | Commit burn then crash before/after handoff; no source-zero or missing-submit inference releases budget |
| Source CAS | Commit terminal and lose reply; current recovery finds one exact application, including original pending obligation |
| Usage | Terminal before usage, partial callbacks, malformed/over-bound usage, duplicates and contradictory late usage |
| Account CAS | Lose acknowledgment before/after atomic application-ID plus delta commit; one charge/remainder delta |
| Mixed recovery | Restore each participant independently behind its authority, including account-ahead/source-behind; stay closed until exact replay |
| Owner fence | Restore old worker with cached resolution/application ticket; stale epoch cannot mutate source or account |
| Original binding | Mutate claim/profile/domain/reservation/range or mint a retry alias; exact original resolution lookup fails closed |
| Complete mediation | Every SDK/network callback and financial delta refines a checked broker or account gate |

No hardware-isolation, native storage, complete provider behavior or recovery
liveness acceptance is asserted. Unknown outcomes may safely remain unresolved;
automatic reclamation needs additional qualified evidence and separate proofs.
