* Tag resolution and source admission

The existing Go preparation owner accepts an exact SHA or inherited release
tag, resolves only refs/tags/<tag> to its peeled commit, and compares that commit
with the supplied POO checkout. It rechecks after preparation and in subsequent
source-currentness validation. A same-name branch, missing tag or retargeted tag
cannot substitute for the retained source cut. Package metadata and Policy
assets remain included in its independent pre-call source hash. Tags do not
prove arbitrary filesystem immutability, compiler fidelity or runtime authority.

The native entry remains gerbil build/test. Twelve host cores are used through
the existing resource policy. Dependency build budgets belong to their upstream
owners; the original Weaver runtime/startup/drain gates are unchanged. Neither
an AOT-only result nor a manually fetched old object establishes standard
package acceptance. No package uninstall is used.

* Authorization to execution

Scheme composes admitted Agentic AI Lab Governor/Governance modules, typed
Profile and source-assets. Each complete Cedar document and the exact aggregate
are validated through the existing Rust C ABI under the publication schema.
Typed objects cross the rooted Scheme/Rust SDK boundary; the production Go
control plane obtains compiled source through authenticated gRPC. Source
compilation and publication commit perform no provider send.

Rust compares replay schemas with the immutable schema source supplied by the
current SPEC API. Candidate and authoritative predecessor equality checks remain
mandatory. Test fixtures serialize through the upstream source-identity API,
not a replacement schema representation. Rust evaluates actual Cedar requests,
persists the existing Turso consumption and current fence, and mediates dispatch
and each stream release. An old approval, successful preflight, historical
publication or released dependency label supplies no send capability.

Go keeps publication operation identity and exact outcome recovery. Unknown
staging/publication outcomes cannot activate ingress by guessing success.
Provider exposure after any partial request or response retains the original
claim and reservation; retries and dual restart cannot redispatch or refund it.
This is logical execution ownership in an AI Agent Gateway, not physical
isolation or an exactly-once delivery promise.
