* Decision for the next baseline

Prefer Agentic AI Lab's inherited Gerbil Ascent capability for bounded rule
derivation, clue/context queries and source invalidation. Keep MRR optional,
disabled as a Gateway authority dependency until a workload demonstrates a
semantic capability gap or a measured advantage over that existing path.
Neither engine supplies authorization, balances or a final send capability.

Rules are one capability inside ordinary programmable Scheme/POO composition,
not the definition of Scheme's entire role. Existing relational declarations
may help derive candidates, but a relation named allowed or eligible is not a
Cedar Allow. Reuse public AA capabilities rather than copying their internal
rule files or introducing another governance language.

This architecture cross-review follows
=WeaverProject::DesignProcess=. Responsibilities remain in the root SysML registry;
[[file:../../../dev/sysml/PolicyEvidenceDesign.sysml][the evidence data contracts]] and [[file:../../../dev/sysml/WeaverExecution.sysml][existing component allocations]] are authoritative.
There are no parallel Lean/Quint state machines, production interfaces or dependency
pin changes. [[file:59.27-policy-evidence-architecture.org][The preceding architecture contract]] still governs Policy evidence and the
final effect join. This review does not constitute overall implementation approval.

* When MRR is worth adding

Ascent already covers retained rule evaluation and provenance. Those names alone
do not justify adding a second backend. MRR's strongest candidate benefit is its
typed semantic-query/catalog/snapshot boundary, multi-source relation and lineage
model, and admission of results from physical data engines. Its own result contract
does not establish factual truth or completeness beyond the named scope.

| Workload need | Baseline choice | MRR admission condition |
|---------------+-----------------+-------------------------|
| Bounded capability/routine candidate derivation | Inherited AA/Ascent | No additional dependency merely to evaluate the same rules |
| Context source changes and dependent invalidation | Existing AA context/query/change-feed capabilities | Demonstrate a missing cross-source/catalog property or better qualified reuse |
| Typed cross-source graph queries and physical result admission | Evaluate optional MRR/mrr-data adapter | Exact catalog/query/snapshot binding, complete relevant scope and backend conformance evidence |
| High-volume repeated derivation | Measure existing Ascent first | Matched workload shows benefit including setup, memory, invalidation and recovery cost |
| Budget/history authorization and consumption | Existing Rust deciding authority | Neither Ascent nor MRR replaces it |

The comparison corpus must include full recomputation, unchanged reads, sparse
updates, rule changes, deletion/negation, incomplete input and restart. Measure
time to first usable result, p95 update latency, memory/GC, affected-source fanout
and evidence-generation cost on the same host and resource limits. A source-level
dependency or upstream VM benchmark is not an end-to-end benefit measurement.
No such performance comparison was run in this architecture review.

The default architecture therefore exposes one derived-evidence adapter with a
selected backend. An MRR branch does not create another evaluator running on the
same request in parallel, another Context truth owner, or a mandatory dependency.
Switching backend requires evidence for its semantic/coverage contract; equal
rows do not make Ascent and MRR receipts interchangeable.

* Hard facts: authority protocol, not a rule-engine callback

Soft candidates may rank already eligible routes or routine branches. Hard facts
such as consent, source validity or allowed data purpose affect permission and
must cross an authenticated publication boundary. Agent hypotheses, displayed
clues and rule-produced eligibility labels cannot register themselves as hard facts.

The hard-fact source contract specifies its domain, source authority, update
ordering, projection/rule closure, coverage and freshness boundary. Deleting a
row is not inherently restrictive: deleting a deny or counterevidence can broaden
eligibility. An admitted fact-feed capability permits only its declared relations
and changes. A rule/projection change or undeclared scope requires new review.
The fixed-fact Policy-delta profile cannot certify these transitions.

The target SourceCommand has exactly one variant: Policy publication, hard-fact
intent, or fact-projection candidate. All use the existing Rust source lane and
deciding authority. No MRR coordinator or second durable Session ledger is added.

| Event | Required authoritative action | Safety under uncertainty |
|-------+-------------------------------+--------------------------|
| Accept hard-fact change | Persist original intent and affected-domain pending barrier; assign a Gateway floor | Source-local prepare/change-feed return is not this receipt |
| Derive replacement | Use a frozen admitted source cut, rule/backend closure and declared query scope | Partial fixed point, timeout or missing support remains unknown; retain the barrier |
| Join projection | Match original barrier receipt/pending prefix, source custody, actual predecessor, projection floor and complete artifact image at CAS | Old validation or a copied new fence cannot publish |
| Commit projection | Atomically bind recoverable projection, original outcome and resolution of this intent | Clear only the resolved intent; other pending intents keep the domain blocked |
| Lose reply/restart | Query the same original intent/operation against authority | No absent reply, local checkpoint or empty query proves cancellation or unlock |
| Reauthorize continuation | Reuse the existing canonical-family continuation protocol under a fresh current inspection | Preserve original intent, root/domains and winner; do not mutate/rebase its old attempt |

The Gateway floor is a monotone authority coordinate, not an Ascent/MRR source
generation. Returning to identical rows after an A-B-A update cannot reopen an
old floor. Concurrent same-domain changes retain their own durable identities
and admitted source ordering. Serialization or explicit coalescing must account
for every original intent; settling one cannot discard another. This initial
design conservatively blocks the affected domain while any required hard-fact
intent is unresolved. Fine-grained partial activation is not claimed.

The projection snapshot and evidence references must be durable/recoverable before
their committed outcome is acknowledged. Cache loss rebuilds from that committed
source cut; it cannot reinstall a stale snapshot as current. A failed subscriber
or incomplete Ascent rebuild cannot remove a Rust pending barrier. Final
admission/dispatch/release checks consult the deciding pending/floor state, not
only a formerly successful preflight or source subscription callback.

The effective withdrawal point is the Gateway's durable barrier, not an external
event timestamp. Across a disconnected source, immediate global withdrawal is
not established by this snapshot architecture. A hard-fact profile must define
its admitted freshness/validity contract and fail closed outside it. Profiles
requiring stronger immediate synchronization remain unsupported until their
source-authority ordering is qualified. Do not hide that limitation with a TTL
or a claim that local currentness is global currentness.

** Durable barrier, decision and recovery cut

Barrier admission has one atomic durable unit: the original intent and command
digest, assigned monotone floor, pending-set membership and immutable outcome.
Only that committed unit can produce the authoritative barrier receipt. An AA
change-feed prepare, an Ascent checkpoint or a Go acknowledgment cannot substitute
for it. Before that receipt, an affected caller must stop new local proposals and
reconcile the same operation; it cannot claim the Gateway has already withdrawn
other workers' authority. The guaranteed effective point remains Rust admission.

=PublishedObservation.decisionKind= distinguishes barrier admission, projection
installation and Policy publication. A committed barrier means blocked, not ready.
A projection commit resolves exactly its named original intents and binds the
remaining pending prefix in =FactBarrierResolution=. The transaction installs the
recoverable image and resolution together. A known rejection is an attempt result,
not cancellation of its intent. Timeout, failed derivation, abandoned owner and
source disconnect never clear pending work. The initial profile has no automatic
abort/unlock: continuation must install a qualified replacement; any coalescing
must account for every original intent under admitted source ordering.

On lost commit response, retry/query by the same identity and digest. A historical
success cannot activate the image against a newer floor or remaining pending work.
Recovery must load a mutually consistent authority cut containing intent, floor,
outcome and projection references. Missing/corrupt authority state refuses fresh
use; rebuilding an Ascent cache cannot repair it by choosing an empty pending set.
Protection against a whole-authority rollback still depends on the existing
independent recovery-floor contract and its deployment premises. SQLite atomicity
or a local checkpoint alone does not prove that anti-rollback property.

** Unknown exposure is independent of fact readiness

Reserve the original shared exposure before an effect can emit bytes. Persist
consumption before handing execution to the final executor. A missing or failed
outcome record cannot reset the original claim or reduce that reservation. Neither
barrier admission, projection resolution, Policy replacement nor Session terminal
state is an accounting application. AA/Ascent resource limits bound computation;
they are not financial account reservations.

Current =crates/ledger/src/provider.rs= atomically increments =tasks.held= during
enqueue, persists unknown consumption and the affine dispatch marker, and leaves
the hold unchanged in =complete_provider=. This is concrete conservative retention,
not a complete final-usage settlement implementation. A denied later dispatch does
not by itself prove that an earlier attempt never executed.

The target =AccountingEvidence= reuses the existing account/result owner. It binds
the original reservation, root/claim/budget domain, dispatch observation and unique
account application. Release only the exposure justified by an authoritative
no-execution result or qualified final usage, through an atomic application-ID and
balance update. Incomplete usage keeps the unresolved exposure held. Account
recovery must preserve that application and its reservation-consumption record;
an ambiguous write is reconciled under the same ID rather than applied twice.
Invocation or response-release completion alone supplies neither receipt. The
initial safe behavior may retain a hold indefinitely; recovery liveness and
settlement integration remain open obligations, not permission to expire it.

Internal charge ceilings require an admitted usage/cost mapping and billing scope
before they can mean external monetary limits. No commercial provider charging
guarantee follows merely from the ledger's bounded integer allowance.

* Artifact bindings that survive rule and cache changes

The fact-projection closure covers the backend/engine, rule module, query and
coverage semantics, source-cut identity, limits and projection adapter. Bind it
to ArtifactImage, the original assurance profile and the exact source intent.
Ascent's generic session copies row spines but can share nested host values:
the adapter must freeze or validate owned immutable values before hashing. A
retained object reference or mutable nested value is not an immutable artifact.

For a negative conclusion, require a completed admitted query over the exact
declared closed scope and current source/rule cut. A bounded nonmembership witness
does not prove absence of spending, a revoked consent, or a fact outside that
query. Ascent's unknown/conflict outputs remain evidence categories, never permits.
Both a rule replacement with identical output and a source replacement with an
old retained handle require currentness checks; reuse computation only within
its qualified dependency closure, never reuse an allow decision.

* Session progression: record, propose, admit, execute

Record an authentic late execution receipt under its original logical effect
even when current facts no longer permit progress. Recording history must not
restore its old authorization. Let the existing AA Session owner derive a
successor proposal; do not call its native-worker completion API with an
unverified gRPC payload or equate local terminal publication with a Rust effect.

SessionProgressionProposal binds the original routine graph, predecessor effect
and required observation domain, successor step, transition slot, current routine
frontier and fact floor. Rust validates that graph edge and dependencies at the
existing successor admission/claim boundary. Observation validity alone is not
progression authorization. A withdrawal between Scheme validation and admission
blocks the proposal, and another withdrawal before dispatch blocks execution.

Deduplicate by the original root/transition slot and permitted successor claim,
not a new receipt, attempt, worker or Session label. Concurrent owners may compute
the same proposal, but the existing original-node claim/outcome mechanism admits
one logical opportunity. Reconcile lost admission replies before retrying that
same command. A restored Scheme checkpoint rebuilds from authoritative claims
and receipts; it cannot skip a dependency, create a fresh family or clear an
unknown predecessor obligation. Local Session revision is not the Rust frontier.

The target successor admission transaction must bind the transition-slot winner,
original successor claim, required reservation and immutable operation outcome
together with the frontier comparison. A local advance followed by a separate
claim call leaves a crash/race gap. Reuse the existing original-node deciding
transaction; the additional graph/frontier binding is still unimplemented.
Lost-response reconciliation may recover a historical winner but cannot rewind
the current frontier or create a second successor reservation.

Invocation completion, response release and accounting application stay distinct.
Only the original step/profile's required observation domain can justify a
successor. A partial stream can be historically true and still block progression;
a completed provider call never proves a budget refund or successful client
delivery. Conflicting terminal receipts go to authoritative reconciliation, not
to a rule that chooses the most permissive result.

AA's Session =view= explicitly marks source authentication, action authorization,
provider disclosure/result admission and durability false at its local host
boundary. Preserve that honesty in the Gateway adapter. Record a verified receipt
first, propose the original graph edge second, then join its current required
fact domains, pending prefix, frontier and receipt domain at Rust admission. That
admission is not final dispatch authorization: the final guard runs again before
new bytes. An accounting-dependent successor requires the account application
receipt, not an invocation-complete label. No new Session ledger is introduced.

*** Exact closure, not equality of output rows

The twelve coordinates are backend, engine, rule, query, schema, source cut,
source authority, scope, limits, adapter, captured callback environment and
freshness contract. Each mutation has its own deterministic rejection test.
Those tests renew the freshness witness for the changed contract before trying
the old derivation, so an unrelated expired witness cannot hide a missing closure
comparison. A rule change can legitimately produce the same rows but needs its
own bound derivation and admitted authority. Source-cut changes likewise retain
the original pending intent, claim and budget/history domains.

A valid projection must also match the immutable original intent's proposed cut.
=validNewCutCannotResolveOtherOriginalIntentTest= rejects a fully derived and
fresh new image against an unrelated pending intent; the matching positive trace
=originalIntentCanInstallItsProposedCutTest= installs and uses the intended cut.
The Lean =unrelated_source_cut_cannot_resolve_intent= lemma makes this binding an
explicit semantic premise. This slice does not implement coalescing or prove
recovery liveness when overlapping intents require a separately authorized
supersession; it preserves them rather than silently resolving the wrong one.

Source inspection grounds the reuse boundary: Ascent
=program/update-selection.ss= qualifies registered stable procedures, immutable
scalars and supported providers for completed-result reuse. It does not certify
arbitrary higher-order Scheme callbacks or serialize their captured environment.
Opaque callbacks require full recomputation; hard-fact use additionally needs an
admitted evaluation/source contract. AA's =clue-exchange.ss= binds owner/source/
prefix/rule context and checks it again after query completion. Reuse those
mechanisms rather than trust a Gateway-created eligible label.

*** Closed-scope completeness and pointwise analysis

The bounded fixture has required scope ={1,2}=. A completed query over ={1}= cannot
prove absence of counterevidence at 2, even when its returned rows are empty and
its producer calls it complete. The admitted source/query contract must establish
which universe is closed, how it maps to the original semantic domain and whether
the engine completed that scope. Timeout, failed rebuild, missing source or
unsupported coverage is unknown. The fixture's counterevidence marker tests this
binding; it is not a replacement Cedar evaluator or proof of general Ascent truth.

A Policy implication theorem compares two Policies in the same fact/entity
environment. Even the same predicate can deny in one world and allow in another.
The new Lean countermodel states precisely that pointwise reflexivity does not
imply a cross-world comparison. Its use does not alter cedar-poo-spec semantics.
Fixed-fact delta evidence cannot resolve a fact intent or activate a projection;
the existing source-authority protocol still owns that change.

*** Owned values and callback dependencies

Ascent =program/session.ss= copies outer lists and row pairs but explicitly shares
nested host values. The model therefore distinguishes the captured immutable
value from a later mutable host value. Detached publication/use continues to read
the captured value after caller mutation; re-reading the alias violates the
binding. Admission rejects an unowned candidate even before a mutation is seen.

Re-freezing an alias after mutation is also unsafe if it retains the old source
cut. The model now stores immutable source-image bindings: one cut cannot name
different committed rows or values, including when revisited after another cut.
Derivation must match that committed image before hashing; a trusted reload may
restore the named immutable input, while a genuine input change needs its own
admitted cut. =mutatedInputCannotRehashUnderOldSourceCutTest= and
=rehashedAliasUnderOldCutCounterexampleTest= pin this distinction. It is grounded
in AA =query-provider.ss= rebuilding the canonical source and comparing its
semantic digest. New Lean lemmas reject materialized values/row digests that do
not match the committed source image.

This is a conditional ownership model, not a proof that a real deep copy, hash
encoder or FFI buffer is safe. Initially admit known immutable canonical value
forms; reject unsupported nested objects. Do not solve this by hashing an object
reference or claiming all Scheme procedures are pure. Higher-order Governance
remains available through existing AA generic methods, with explicit module,
captured parameter and source-dependency contracts as described in
[[file:59.25-openshell-and-tao3k-ecosystem.org::*Higher-order Governance is a first-class capability][the Scheme composition architecture]].

*** Freshness profiles and their effective boundaries

Freshness mode is fixed by original admitted source/Profile authority, not chosen
by the agent at use. Both modes bind source authority, exact cut, scope and
contract, plus current executor fence and clock epoch:

| Admitted mode | Required source promise | Disconnect/restart boundary |
|---------------+-------------------------+-----------------------------|
| Ordered source session | Qualified source ordering makes permission-affecting changes effective through the durable Gateway barrier, with current authenticated session/request identity | A detected disconnect blocks new uses until current authoritative revalidation; a connected socket alone proves no such ordering |
| Bounded source promise | Authenticated source commits that this cut/scope remains usable strictly before the named deadline, or orders its invalidation through the Gateway barrier | Existing promise can permit disconnected use before expiry; exact expiry rejects. Restart requires a current clock/owner epoch and renewed authority; cached local TTL is insufficient |

The second profile is unsupported for a source that may independently revoke
immediately without honoring that promise/order. Neither mode proves immediate
remote withdrawal during an undetected partition. Fail closed when the admitted
contract cannot establish validity; do not label last-known data globally fresh.
The monotone clock/floor and epoch are Host/deployment premises; restoring all
clock and authority state from one old snapshot is outside this model's guarantee.
