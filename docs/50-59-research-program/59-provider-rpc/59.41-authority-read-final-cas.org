* Decision and ownership

Responsibilities remain in =Project.sysml= and =WeaverExecution=. Scheme/AA owns
admitted higher-order Governance semantics. Go freezes source commands and
recovers their exact original outcomes over authenticated gRPC. Rust owns the
actual deciding state, current Cedar evaluation, claim/hold transitions and
final transport boundary. Existing Lean proves conditional semantic refinement;
existing Quint explores ordering and faults. No additional state-machine owner
or policy language is introduced.

Historical publication receipts prove a past decision, never the active head.
A current read is a witness to recheck, not an execution permit. Final use must
join authority identity/revision, original profile payload/source, canonical
claim, shared budget/history coordinates and executor fence under one deciding
serialization boundary. A lost response does not abort a commit or release a hold.

Queued-only recovery can refresh observation revision/fence under the existing
enqueue transaction after fresh authorization. =ProviderPlan.digest= excludes
those observations and retains the actual body/routes/profile commitment.
Refresh preserves the original operation, claim and hold. An already consumed
operation does not become queued again. This safety-preserving progress path is
different from replacing the original semantic contract.

The final dispatch has two transactions: persist the dispatch burn, then recheck
current authority under the lock held through the bounded send callback. A
commit between these transactions can invalidate sending; the original burn
and unknown hold remain. A callback already admitted under the lock may finish
before a waiting publication commits. This is the linearization rule, not
instantaneous cancellation of bytes already admitted to transport.

Opening a new Ledger creates a local handle session; it does not elect a new
cluster owner or globally fence a live peer. A real handoff must durably advance
the authority fence before activating the new owner. The old-worker tests here
include that explicit fence change; process startup alone is not a custody proof.

No proof imports a new dependency revision. The upstream Gateway publication
library is a semantic reference; Weaver's unchanged pin does not yet provide
its full runtime integration. No new copy of its object Contract or of the
existing publication/execution state machine is created here.

The whole-store rollback Quint witness retains an external-call trace observer
while restoring local source/execution state. The observer is not an implemented
counter service. It demonstrates that a self-consistent local snapshot can pass
local checks while forgetting an already performed effect.
The publication itself remains unchanged in this witness. A recovery floor that
only covers publication revision therefore cannot catch it. The independent
commit floor must cover execution consumption, account applications and history
prefixes as well. Unknown cross-store floor/data commit outcomes retain the
original claim and hold until exact reconciliation; a new nonce or owner session
cannot repair this by allocating fresh capacity.

The next [[file:59.42-independent-commit-floor.org][independent commit-floor review]] closes the target protocol for all
four prefixes, exact outcome recovery and the independent transport owner. Its
SQLite protocol reference composes with actual Ledger dispatch but does not
install a production floor. AC-06 remains an expected unsafe production witness.

Revision normalization remains explicit: the Lean recovery proof uses head zero
for absence and one for the first committed entry; Quint/native wire revisions
use minus one/absence and zero for the first entry. The Host refinement maps
committed ordinal to Lean head by adding one and retains the native integer
bounds. Comparing these representations without that mapping is not proved.
