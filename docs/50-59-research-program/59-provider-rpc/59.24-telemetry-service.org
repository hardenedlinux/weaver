#+TITLE: 59.24 Default Telemetry Service and Architecture Differentiation
#+LANGUAGE: en

* Top-level service decision

Telemetry is now a default local service in both running components. Rust's
=ServiceRuntime= owns =weaver-telemetry=; the Go Gateway owns the matching
=go/internal/telemetry= recorder. Neither needs a worker, queue or exporter.
Both use the existing authenticated =InspectTelemetry= gRPC method. Rust permits
it only on source ingress and rechecks the current source authority. Go applies
its existing control-plane mutual TLS and credential interceptor. No new listener
or external destination is enabled.

The implemented vocabulary has nine fixed counters: successful/failed compilation,
admitted/completed/failed provider handlers, response frames queued, queue wait
failures, rejected RPC authentication and snapshot reads. Rust compilation failure
counts owned compiler-job failures; it is not a count of every rejected source
request. Provider completion counts a handler result, not exactly-once delivery.
Queued or forwarded frames do not prove peer receipt. No metric is a coherent
authority snapshot, readiness acknowledgment, usage receipt or no-execution proof.

Counters use fixed storage, saturate instead of wrapping, and accept only closed
signal kinds. Prompts, response text, Policy bodies, credentials, identifiers,
arbitrary labels and propagated trace context cannot enter the recorder API.
Updates perform no IO or callbacks. Their compare/exchange retry loops are
lock-free rather than wait-free; no hard latency bound is claimed under contention.
Restart resets local counters; durable consumption and unknown holds remain in
the existing MRR Data/Turso boundary. Rust and Go observations are separate views,
not a globally synchronized total.

OTLP export, sampled traces, a security event bus and durable audit are still
unimplemented. The destination/credential publication and Policy requirements
below apply before enabling any exporter. The local recorder exposes no exporter
configuration that could silently bypass those requirements.

Current Go producers emit local structured startup/source-process phases through
standard =slog=. Fields contain fixed phase names, elapsed time, child PID,
outcome/cancellation categories, byte count and host-wall timestamps. They exclude
source paths, source/Policy bodies and credentials. These ordinary stderr
diagnostics do not deliver the target event bus, nonblocking exporter, loss
accounting or durable security audit. A PID is not an authenticated incarnation.
The native integration fixture also emits fixed labels and Gerbil toolchain CPU/real/host-wall
clocks. Trusted operator code can forge that text; it never selects a claim,
authorizes publication or proves process quiescence.

Child reaping, artifact decoding, authority reconciliation and issuing Serve are
separate observations. Tests still require authenticated readiness and natural
exit. Clock-domain and failed sampling evidence is retained in
[[file:59.39-ffi-local-results.org][the installed-prefix qualification chapter]].

The service observes Scheme source compilation, Go publication/routing and Rust
authority/dispatch/release events. Default collection is local and bounded.
An external Collector is an explicitly configured destination with authenticated
transport, permitted signal categories and an export Policy. Anonymous product
analytics is outside the default service.

| Signal | Default content | Failure behavior |
|--------+-----------------+------------------|
| Metrics | Bounded-cardinality latency, queue capacity, denied operations and dropped-event counts | Loss is measurable and cannot grant execution |
| Diagnostic traces | Opaque correlations and component/stage status | Bounded sampling; untrusted remote propagation is sanitized |
| Security events | Command/content identity, revision/fence and normalized decision/result categories | Link to authoritative records; never substitute for them |

Prompts, response bodies, credentials, raw Policy text, raw tool arguments and
asset paths are excluded from default attributes at event creation. Collector-side
redaction supplements this producer rule. Tenant-scoped identifiers require
explicit access and retention rules. External trace headers and baggage are
untrusted input; they cannot select a canonical claim or authorization context.

* Authority, audit and availability

The deciding ledger remains authoritative for consumption, settlement and unknown
holds. Telemetry acknowledgment cannot acknowledge a publication, prove no
execution or release budget. Durable audit obligations, where required by Policy,
must use an authoritative commit/evidence protocol and cannot be implemented as
a best-effort trace exporter.

Producer submission must be bounded and nonblocking on the effect path. Collector
failure cannot change a deny to allow or reconstruct a lost send capability.
Overflow must increment a loss counter and retain service health visibility.
Exporter retries must carry event identity and never call the execution broker.
An export destination or credential change requires the same explicit publication
and currentness discipline as other governed capabilities.

Delivery gates include payload-field exclusion, hostile trace context, collector
stall, queue exhaustion, export reply loss, shutdown and restart. Tests must show
unchanged claim/held-budget/dispatch state for telemetry-only transitions. No
telemetry security proof is claimed before those implementation witnesses exist.

* Implementation validation

The existing Go development driver provides the composed entry:

#+begin_src text
go -C go run ./cmd/weaver-dev -clean-source check-telemetry
#+end_src

It joins strict model/ownership checks, Rust ASP/unit properties, Go race/PBT,
real mTLS provider fault/recovery tests, Quint schedules, Lean JSON and freshly
collected package benchmarks. The compact receipt stays under ignored
=.cache/verification/=; no individual process log becomes a repository asset.

Rust proptest and Go quick.Check exercise monotonic recording, saturation and
process-local reset. Twelve concurrent writers retain every completed observation.
The new Rust package retains the workspace ASP deny gate and its own thirty-sample
Criterion record/snapshot benchmarks, registered in the existing Go benchmark
inventory. No runtime dependency pin is changed.

Real Go integration starts the Rust authority and Go control services over mutual
TLS. A partial provider response retains its original hold through generated
telemetry-read sequences and process restart; repeated execution still fails and
provider call counts remain unchanged. An operation-role connection cannot read
Rust source-side telemetry. A second test observes both live components after an
actual complete stream. Existing revocation, source recovery and partial-write
tests remain necessary; counters never replace their receipts.

Quint adds telemetry stuttering and an unsafe-refund counterexample to the
existing =TursoMvcc= model. Lean extends =RuntimeAdmission.MVCC.EffectImage= with
a separate statistical projection: arbitrary finite observation traces preserve
the execution image, and counter reset preserves spent-state and unknown holds.
These laws assume the runtime recorder has no ledger/transport callback and that
the existing durable owner recovers the original effect. They do not prove the
native binary, atomic instruction timing or an external exporter.

* OpenShell reference and Weaver leverage

The fuller [[file:59.25-openshell-and-tao3k-ecosystem.org][OpenShell and TAO3K ecosystem review]] separates Scheme's programmable
semantic role, Cedar proof reuse, runtime delivery and optional containment.

The research checkout is =.data/openshell=, with origin
[[https://github.com/NVIDIA/OpenShell][NVIDIA/OpenShell]]. The inspected snapshot is
=3a5dfcd2f1afd9c7376b07b11036265bbb68453c=.

OpenShell separates operational observability from anonymous product telemetry.
Its observability includes OTLP gRPC, metrics and OCSF security events. Its security
architecture includes sandbox/supervisor enforcement, endpoint-bound credentials,
dynamic network policy and an SMT Policy prover. Weaver should learn these
mechanisms without claiming that OpenShell lacks formal checks or semantic API
controls.

Weaver's target advantage is a reusable task-to-effect contract: Scheme Profile
and Governor composition; Cedar-constrained routine/routing selection; Rust-owned
consumption, shared holds and per-message release; and evidence that relates
source, authority and fault behavior. Model count, language count and log volume
are not measures of security advantage. Each supported protocol/provider must
retain original claim, budget/history and semantic commitments through retry,
fallback and reconnection. Features remain proposals until mapped to actual tests
and model/proof witnesses.

Priority is the implemented Cedar Policy/source-asset publication chain, then
governed routing/routine extensions and the bounded telemetry delivery gates.
Go owns cloud-native configuration and protocol integration; Rust owns final
effect capability and backpressure; Scheme owns semantic composition. A sandbox
runtime may be a deployment backend without replacing these logical boundaries.
