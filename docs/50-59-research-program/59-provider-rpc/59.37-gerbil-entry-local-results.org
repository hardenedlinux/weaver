* Failures that led to the final declarations
The first new-entry preparation attempt failed: links alone lacked the
package-manager dependency manifests. Core and project builds failed, and the
following test stage timed out. The static ownership check still expected the
old root parser, and development inputs changed during that diagnostic run.
That complete =check-scheme= receipt remains =FAIL=, not a sixteen-stage pass.

The next standard-build controls retained these distinct failures:

- Putting an =exe:= into a production Module spec was refused with
  =native programs require an explicit init-owned test demand=. The final
  development declaration uses that existing demand rather than bypassing it.
- The program initially omitted =export main=; the native linker correctly
  refused it. The final module exports its executable entry.
- The installed SDK retained a stale OpenSSL Cellar link path. Environment
  pkg-config metadata supplies the existing OpenSSL 3 ABI; the executable
  declaration requires =libcrypto < 4= and rejects the host's default OpenSSL 4.
- The inventory imported the test tool without using it. Native linking exposed
  missing installed static tool objects. Removing that unused import leaves
  the actual SDK expander dependency; no runtime or test assertion is removed.

The final production and development commands then completed naturally. The
earlier image-inventory and gxi fifteen-second failures remain recorded in
59.35 and are not reclassified. This evidence qualifies the corrected public
entry, not a newly successful complete fresh-prefix =check-scheme= cohort.
