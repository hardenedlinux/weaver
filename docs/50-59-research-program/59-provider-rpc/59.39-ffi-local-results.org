* Ordinary source startup observations

control configuration/authority/Serve phases without source paths or payloads.
The existing Scheme fixture library records module readiness, entry, compile-begin
and artifact-written. SDK CPU/real clocks and host-wall microseconds remain
distinct: subtracting a Go elapsed clock from the SDK real clock is invalid.
Host-wall calibration assumes no intervening clock adjustment. Only actual Wait
proves that child was reaped; phase text cannot certify descendants, durable
publication, natural exit or readiness.

The historical timeout is not declared repaired. An initial eight-slot
experiment cloned dependency prefixes, removed product libraries, rebuilt them
with =gerbil build= and used the same =gerbil test -g -v 5 t= command. Its first
three completed observations were:

| Slot | Output boundary | Runtime result |
|------+-----------------+----------------|
| 0 | Regular file with a diagnostic read observer | FAIL, 15.008740250 s, no Harness output |
| 1 | Drained pipe | PASS, 11.740627584 s, terminal result at 9.879834250 s |
| 2 | Drained pipe | FAIL, 15.013553084 s, no Harness output |

The enclosing Go test hit its unchanged ten-minute default watchdog during the
fourth build. That batch is incomplete, not a qualified paired matrix. Its SDK
build processes subsequently finished naturally; the unobserved fourth slot is
not assigned a result. A setup attempt also refused GNU =cp= with BSD clone
flags; the diagnostic now uses the existing Go/x/sys Darwin =clonefile= API.
Independent slot invocations and immutable, source-bound compact receipts
replace the failed batch organization; neither watchdog is increased.

The pipe failure falsifies the claim that replacing regular-file output alone
reliably repairs cold startup. This initial batch does not separate host load,
page/signature caches, inode identity or observer effects. Cold scope means new
prefix paths and fresh product-library builds; it is not an OS-wide cold boot.
The optional image study holds output constant and varies cloned versus
hardlinked dependency-image identity. Shared seed hashes are checked before and
after, and product images are always removed/rebuilt. An unrun study is not
evidence for a causal conclusion.
