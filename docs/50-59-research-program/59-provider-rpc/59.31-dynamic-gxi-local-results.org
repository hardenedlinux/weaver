All eight coalesced trials completed the nineteen original cases, checked the
standard runner's return value, returned to the caller, exited naturally with
status zero, and left no owned process group. No semantic warning was accepted.
Their complete test output matched the original installed-layout control:
=cccd626ac86312776e83fcf28bb2707ea1d0e015ccbfae810fd0fbc12239d97b=.

All eight separate-layout counterfactual trials remained failures. The
watchdog cancelled them at the unchanged deadline; cancellation is not a
successful exit or cleanup witness. The matrix PASS applies to the repaired
layout and preserves these failures explicitly. It does not assert that the
unrepaired layout met the deadline.

The ordinary original installed-layout observation completed in 10.558789 s:
the checked runner returned at 8.786118 s, leaving approximately 1.773 s of exit
cleanup/drain. For coalesced first use, execution between =HARNESS= and
=HARNESS-OK= took approximately 0.074--0.190 s, and cleanup/drain after caller
return took approximately 0.061--0.077 s. Discovery/loading remains the larger
first-use component. The slower repeat in generation 2 is retained; this is not
a best-sample report.

Selected image first use is distinct from an OS-wide cold boot. Installed
runtime and foreign leaves, source pages and host services remain shared.
Neither this matrix nor load-average snapshots prove that unrelated host
activity has disappeared. The reproducible repair is fewer mappings with the
same logical entries; no universal latency or exact source-only speed ratio is
claimed.

* CI sparse-checkout source ownership correction
The first private run, =41062328472= at =8296f11=, failed all seven jobs before
their test suites began. The common source inventory required the observer
inside =dev/proofs/evidence/=, while the workflow deliberately excludes that
historical archive from its sparse checkout. The secondary missing-receipt
message did not indicate a native runtime failure. This failed workflow is
retained as a separate receipt and does not replace either local result above.

Active observer source now lives in =dev/scheme/module-observer.c=; the sealed
historical copy remains intact. The copies are byte-identical, with SHA-256
=c3d9f9b044d2ae47a86631ee0e66a82d3b31f162ef9f5ff96d1d1f7c99320eab=.
The common inventory and diagnostic compiler reference the active source.
Neither the ordinary gxi arguments, module packager, runtime code nor pins
change in this correction. The frozen local performance claim remains bound
to =14c746e= and its recorded digests, rather than being relabeled as a new run.

The focused Go regression materializes only the live source inventory into a
temporary tree with the same archive exclusions as CI. Restoring the old
archive reference reproduces the missing-file failure; the corrected inventory
passes with exactly equal source hashes. Race-checked runner controls and the
Darwin C compiler check also pass. CI keeps its archive exclusions; fetching
all historical logs is not the repair.
