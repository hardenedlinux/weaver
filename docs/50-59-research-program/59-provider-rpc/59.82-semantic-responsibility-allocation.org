* Normative model

[[file:../../../dev/sysml/WeaverExecution.sysml][WeaverExecution.sysml]] owns the allocation. The existing parts contain typed
actions, rather than introducing another issuer, coordinator or source ledger:

| Existing owner | Allocated action | Contract and boundary |
|----------------+------------------+-----------------------|
| SchemeSemanticPublisher | DeriveSemanticCandidate | Independently admitted SemanticCommitment to inert SourceCommand |
| SourceControlAdapter | OrchestrateSourcePublication | Preserve the original while submitting an authenticated SourceCommand |
| RustLedger | CommitOriginalAdmission | SourceCommand to PublishedObservation under current authority and durable CAS |
| RustFinalBroker | GuardFinalEffect | ConsumedPermit to actual wire request under current final custody |

Action signatures allocate responsibilities; they do not establish an executable
refinement, sufficient authorization or a theorem about external delivery. Existing
ports and connections remain the communication topology. No action creates a new
service or permits a shortcut between source compilation and external bytes.

* Scheme semantics and upstream reuse

** Governance and Governor are separate upstream responsibilities

| Agentic AI Lab public owner | Meaning | Weaver integration |
|----------------------------+---------+--------------------|
| =modules/governance/interface.ss= | Engine-neutral Profile, threat model, assessment and open generic dispatch | Configure an upstream Profile; retain only gateway-specific exact source/context binding |
| =modules/governor/config.ss= | Public module-selection bundle for the loop governor; other standalone role files currently publish no additional bindings | Reuse the existing upstream composition mechanism rather than declaring a second selection language |
| =modules/loop-engine/control/governor.ss= | Public facade for actual governor objects, policy classification and contract projection | Project eligible symbolic nodes to gateway identifiers; retain upstream denylist, state conflict and aggregate-selection rules |

Keep these contracts separate under the common upstream library. They can be
configured together without merging assessment and selection into one method.
The current directory named governor is largely a selection facade, whereas its
kernel lives under loop-engine/control. This naming/layout does not make it a
second Governance framework. No upstream directory or module identity is renamed
by this change.

Weaver's =GovernanceScopeContract= now exposes only the specific typed =assess=
method. Gateway compilation calls the upstream governor facade directly and
performs only symbol-to-string projection. A caller-supplied =Governance.open=
slot cannot replace that selection. The POO Record/Function boundary and the
upstream Governor object contract remain distinct, composable checks.

Upstream configuration bundles select modules and features; actual objects are
explicit caller values. A Profile is extended through upstream POO inheritance
and generic dispatch. Configuration must not acquire ambient send authority.
Existing =init.ss= declares the local adapting scopes, and =gerbil.pkg= declares
Agentic AI Lab as the inherited dependency. No nested package, extra framework
DSL or independent Yuanxu dependency is added.

Framework-level Profile protocols, governor algorithms and reusable module
composition belong upstream. Gateway-specific source projections, Cedar provider
adaptation, authoritative publication and final execution remain downstream.
The exact source/context snapshot checks still live in Weaver: their gateway
wire fields are application-specific. Further extraction must establish a public
upstream contract first, rather than moving code and importing private files.

** Semantic and execution allocation

Scheme owns routine meaning, original task scope, required parent profiles and
permitted derivation or alias relations. Reuse Agentic AI Lab Governor selection
and Governance assessment, obligations and source assets. Reuse inherited specific
Record/Function contracts and the existing typed Scheme-to-Rust FFI handoff.
JSON/YAML fills the same admitted data contracts; no second governance DSL is needed.

An original binds claim, profile commitment and shared budget/history domains.
Routing, fallback, protocol reconnect and source replacement preserve that meaning.
Scheme proposes a candidate; it does not commit consumption, settle reservations,
own provider credentials or send bytes. An assessment success cannot release an
unknown hold. Semantic alias derivation does not authenticate its own input.

Cedar and cedar-poo-spec own reusable authorization semantics and conditional
preservation laws. Rust supplies authenticated actual effect/state to the existing
Cedar mechanism. Lean checks the imported semantic contracts under their explicit
premises; Quint explores interleavings and counterexamples. Neither tool replaces
current context acquisition, durable transactions or final transport mediation.
Only declarations checked against the pinned dependency count as imported proofs.

Go owns configuration normalization, cloud/protocol integration, route proposals,
authenticated publication orchestration and uncertain-outcome reconciliation.
Rust owns the FFI lifetime boundary, typed original comparison, current actual
context, MRR Data/Turso deciding transaction, consumption and final-use fencing.
This keeps programmable semantics out of duplicate Rust/Go policy interpreters
while retaining the necessary durable execution mechanisms.

* Existing implementation and remaining gap

| Existing mechanism | Reuse and limit |
|--------------------+-----------------|
| =crates/governance/src/catalog/admission.rs= | Immutable approved producer catalog; trusted embedding supplies the original, so construction alone does not authenticate its truth |
| =crates/governance/src/binding.rs= | SourceExpectation captures before compilation; BoundSource requires typed equality, not agreement between two caller-selected aliases |
| =crates/server/src/grpc.rs= | compile_source checks actual source authority before and after the bounded compiler call; returned data remains inert |
| =go/internal/controlplane/source_compile.go= | BootstrapProducer retains the original-bound artifact and rechecks source authority; successful compilation grants no send right |
| =crates/ledger/src/task_origins.rs= | Existing source transaction persists task/origin/domain commitments and exact admission outcomes; final use rejects missing bindings |
| =dev/proofs/cedar/WeaverPolicyBridge.lean= | Existing registered-original and matched-context composition laws retain authenticated-original and runtime-refinement premises |

The accepted runtime still trusts issuance of the stable original task key.
Changing task_key, family and origin together remains the explicit issuer-trust
counterexample in [[file:59.81-original-task-origin-registration.org][59.81]]. Matching body content cannot distinguish a replay
from genuine independent work. A SysML allocation is not evidence that this gap
has been closed.

The next implementation must bind the independent original through the existing
catalog/capture, authenticated source publication and original-task transaction.
Before adding any field or CAS, identify the missing provenance coordinate and
its authoritative source. Reuse existing outcome recovery and source fencing.
Do not introduce parallel issuer credentials, another ledger or content deduplication
as a substitute for that binding.

* Model validation and delivery gate

The standard Scheme suite uses the upstream POO property framework to generate
denylist/state combinations. It checks that an injected Governance selector is
never called, blocked nodes cannot reach assessment and eligible nodes still
require assessment. The existing 128-case callback/image property retains its
mutation checks; its former selector phase now checks that the removed callback
is ignored, rather than preserving a nonexistent dispatch hook.

The Quint boundary independently requires =governorChecked= and
=governanceChecked=. Its missing-Governor negative control admits the unsafe
boundary only through the deliberately unsafe action and witnesses invariant
failure. Lean proves neither accepted check can replace the other. These are
composition laws conditional on runtime refinement; they do not prove the
upstream classification algorithm, identity provenance or final transport.

=TestSysMLSemanticResponsibilityAllocation= queries the linked strict OpenSysML
model for the four typed action owners and rejects allocation of GuardFinalEffect
outside the Rust broker. =TestSysMLSDKAndRequirementTrace= retains the named
GovernorSourceHandoff trace and complete requirement inventory.

These checks establish model structure only. Runtime closure still requires
actual original-provenance integration, an all-label rename negative control,
lost-publication-response recovery, source handoff and restart with unchanged
claim, shared exposure and history. Existing Quint and Lean issuer premises remain
explicit; no new behavioral proof or runtime acceptance is claimed by this change.
