[[file:../../../dev/proofs/quint/LlmIncarnationIssuance.qnt][Quint]] models expand category 43's enrollment sequencing without modifying its

source or dependency pin is changed; no native ABI qualification is inferred.

One source-level boundary is intentionally stricter: P12 rejects only when now is
greater than expiry, while Gateway activation requires now strictly before the
target deadline. Equality at the deadline is denied here. Native reuse must
implement that explicit boundary rather than silently assuming the same validity
comparison. P15's monotonic-clock check and P43's coordinate-exhaustion rejection
are reusable patterns, not proofs of persistent clock floors or bounded codecs.

Lean uses a Bootstrap context containing workload/key/session facts. It does not
require the new incarnation to be authenticated before it exists. Possession
requires a native verification witness for the complete Ticket and the exact
bootstrap key and session. The registered future incarnation is instead frozen
by independent launch authorization. From an empty registry, issued_was_authorized
traces every accepted row to that actual issue transition; the activation theorem
combines this provenance with the exact persisted proof and current activation CAS.

The predecessor's enrolled predicate is made logically true only in the projected
custody machine. This is explicit semantic factoring: the new outer layer supplies
the issued/proven/current guard at each fresh-incarnation activation. It is not a
claim to have proved the old arbitrary native enrolled predicate. The actual
predecessor custody transition still supplies authentic recovery authorization,
immutable scope, fence/serial progression and the exact custody publication.
The weaker projected enrolled=true relation must never be exposed as an alternate
native API. Inner durability predicates describe projections of the same outer
commit; implementation must not activate an inner grant before that whole event.
Native persistence is a predicate over both complete pre-state and post-state;
pre-state durability alone cannot acknowledge an issued ticket or activation.

The modeled route is fresh-incarnation custody handoff. Same-incarnation key
rotation from category 43 is not expanded by this layer and cannot be claimed
qualified by these checks. It needs its own qualified bootstrap/rotation protocol;
there is no implicit rotation/rebinding fallback in this model.

The original-result/account proofs compose actual predecessor runs and require
initialized publication/custody/account prefixes. Budget results retain Safe
handoff and the authentic original reservation/source binding. The unknown-usage
theorem is conditional on that source remaining unmetered; identity sequencing
does not prove source truth or financial settlement correctness by itself.

* Quint projections and counterexamples

The finite fixture begins at the predecessor's actual armed original operation.
It uses two canonical launches with frozen distinct keys/sessions and two candidate
issuance IDs, plus the old worker sharing their workload principal. Proof receipts
retain full ticket projections rather than just a proof ID. Activation outcomes
are represented by an applied-ID set and the corresponding immutable ticket target;
Lean stores the full outcome grant. No automatic Quint-to-Lean refinement proof
is claimed. Both models separately constrain the actual inherited custody chain.

| Mutation | Concrete failure | Limit |
|----------+------------------+-------|
| sharedIdentityIssuanceCounterexampleTest | Omitting the bootstrap guard lets the actual inherited handoff activate the new capability for an invocation with the old key/session | No provider call or floor admission occurs |
| noProofIssuanceCounterexampleTest | Actual capability activates without a persisted proof receipt | Outcomes/proofs relation fails, in addition to the qualification monitor |
| revokedProofIssuanceCounterexampleTest | A retired issuer-epoch proof activates when the final epoch guard is removed | Actual custody fence/grant advances; no external send |
| keySubstitutionIssuanceCounterexampleTest | An immutable issued row is rewritten to the old worker key | Deliberate registry-corruption/qualification witness, not a claim that the guarded protocol permits overwrite |
| rollbackIssueIssuanceCounterexampleTest | Recovery loses issued/launch/reservation records while proof remains | Cross-projection recovery invariant fails; no native co-rollback detector is proved |
| lostActivationResultIssuanceCounterexampleTest | Recovery loses the activation result while actual active custody remains | Qualification/result-retention violation; it does not demonstrate a second handoff |

Fault actions are outside the guarded random step. unsafeActivate explicitly
requires the normal activation predicate to be false before executing the real
inherited handoff. The independent ITF decoder checks that fact's concrete
key/session, missing-proof or epoch mismatch, actual active grant/fence, unchanged
floor/provider state and retained account hold. Ghost qualification flags are
not presented as transport authentication or native storage evidence.

The first executable attempt caught an unset registry variable in a composed
partial action. Its failure and source snapshot are retained. The repaired model
threads the registry revision/read qualification through every underlying metadata
step, matching the intended outer-owner ordering. Earlier parse/Lean diagnostics
remain separate from accepted current receipts.

freshly checks eleven ancestor source/core hashes, uses official parser spans to
