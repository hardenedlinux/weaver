* Evidence boundary

This review adds actual executable [[file:../../../dev/proofs/lean/LlmSourceCustody.lean][Lean]] and [[file:../../../dev/proofs/quint/LlmSourceCustody.qnt][Quint]] artifacts. It imports the
existing source-join/floor/account chain instead of substituting an independent
counter model. Source identities belong in this evidence document and its JSON
receipts; the [[file:41.02-source-custody.d2][core diagram]] contains only design responsibilities.

The model treats durable arm, fence publication, authentic outcome resolution,
semantic intent equivalence and atomic determining outcome as owner contracts.
It does not implement a storage engine, prove distributed consensus, test native
ABI compatibility, or establish provider-side exactly-once delivery. All upstream
sources and dependency pins remain unchanged.

* Counterexamples and their limits

| Mutation | Observable failure | Repair |
|----------+--------------------+--------|
| oldPermitCustodyCounterexampleTest | Actual inherited append accepts a fresh source join while the outer custody tuple is stale | Check custody tuple at the determining CAS, in the same ordering as transfer |
| unknownCloseCustodyCounterexampleTest | Restarted armed operation closes without outcome | Retain unknown obligations and resolve under a new fence |
| unresolvedCloseCustodyCounterexampleTest | Committed but unconfirmed result closes before authoritative resolution | Resolve original result first |
| droppedIntentCustodyCounterexampleTest | Transfer drops original intent/recovery obligation | Preserve root and pending pins durably |
| wrongResultCustodyCounterexampleTest | Resolution substitutes another proposal absent from the original committed result | Exact original result binding |
| armedMutationCustodyCounterexampleTest | Source revision changes during the modeled custody critical section | Serialize or repeat equivalent atomic final comparison |
| rolledBackFenceCustodyCounterexampleTest | Restored older custody fence violates protected authority continuity | Read current independent authority before resuming |

The last mutation uses a ghost violation marker. It demonstrates the missing
recovery obligation; it does not prove that a local monitor detects co-rollback
of itself and the authority. The old-permit mutation really invokes the inherited
append transition; the remaining descriptor/control mutations do not claim an
actual provider send or duplicate financial settlement. The ITF decoder checks
original source execution and account holds independently of the ghost marker.

* Guarded-model diagnostic

Initial random exploration found that the monitor incorrectly required a local
resolution flag to remain true after an already valid durable close. Restart
legitimately clears local knowledge while retaining the committed outcome. The
retained preliminary model and closed-restart ITF witness reproduce that false
rejection. The corrected invariant preserves the outcome; the close action still
requires current resolution, and the broken close monitor records violation of
that transition precondition. =closedRestartRetainsOutcomeTest= guards this case.
A separate verbose simulator trace attempt hit a Quint trace-recorder assertion;
it is retained as tool failure evidence, not counted as a safety result.

* Reproducible acceptance

Run the isolated checker (retired Python driver); see [[file:../../../dev/proofs/evidence/llm-source-custody/commands.json][command receipts]] and [[file:../../../dev/proofs/evidence/llm-source-custody/receipt.json][final receipt]].
The checker compiles the complete local Lean import closure, prints new theorem
axioms, typechecks Quint, runs guarded and mutation controls, exports ITF traces,
samples nine recovery initializers and regresses the preceding source-join model.
The Quint model imports the actual source-join module and selects six floor
members (the proposal/result types, floor state and three immutable fixtures).
This avoids duplicating a complete second floor namespace. Its 23 new controls
run separately from the preceding model's 103-control regression, which includes
the parent join, floor and account controls. The ITF decoder checks the actual
floor log and handoff tail together, as well as account holds and provider state.
Typechecking still covers the complete model.

Typecheck attempts and a full-control attempt exceeded their unchanged watchdogs;
these are retained alongside the guarded-monitor diagnostic. The isolated checker
can resume already successful Lean compilation only after verifying every source
hash and compiled output exists. This saves repeated compilation without treating
a timed-out route as successful. All failures remain in preliminary logs; they
are not overwritten as passes.

Acceptance requires all command exits zero, no sorryAx in new Lean declarations,
independent ITF decoding, four-artifact links, English Org link/export validation,
D2 validation/render inspection, unchanged prior sealed evidence and dependency
hashes. Finite sampling is bounded evidence rather than exhaustive model checking.
Native custody/outcome atomicity, availability, anti-rollback authority and actual
provider send fencing remain implementation qualification requirements.
