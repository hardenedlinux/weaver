* Lean model, assumptions and composition
Thirty-three printed declarations compile without sorryAx. Nat-indexed registries
and inductive Run cover arbitrary finite populations and traces. Sources derives
canonical row association and native authority provenance from legal imports and
exact-parent rotations. Valid preserves the original Task/Plan relationship.
Joined and Outcome constrain both directions of predecessor Plan publication.
qualified_step derives preservation from guards and updates, not an assumed complete
post-state invariant. History remains qualified after source rotation; live approval
is checked separately.

Owner.subjectSource and producerSource mean configured, tenant/purpose constrained,
authenticated native authority evidence, not a valid JWT from any issuer. taskSource
is the authoritative original task-to-subject/producer and enrollment commitment.
verify requires current credential authentication for both principals plus enrollment
possession over one exact body and current channel/challenge. Public generation/key
metadata is insufficient. Authentic identity-source updates must not be forgeable by
an old worker's ordinary workload credential.

CanApprove binds the stored assignment to exact current subject and producer rows,
full native proof, current policy/source facts, outer revision, predecessor epoch and
original Blueprint. new_plan_has_current_assignment extracts this obligation from
every newly published Plan. new_plan_has_no_credential_effect fixes the entire child
successor to the exact Plan/revision append. NewIssues and new_credential_rechecks_subject
close the later issuance gap after a source rotation. verifyNewIssue is a separate
native predicate over the current outer state, assignment, approval and exact new
credential body. It authenticates this caller using a current credential and fresh
channel/challenge context, not a stored approval proof. missing_issue_identity_rejected
extracts its necessity from every newly admitted credential.

The model separates authentication-key rotation from enrollment-key replacement.
Same-key subject credential renewal and producer-key rotation can reapprove the same
assignment. A changed subject key cannot silently migrate a frozen Plan. Source rotation
alone does not revoke already-issued enrollment credentials; explicit actual predecessor
revocation remains available. Existing historical accounting is not guarded by a fresh
identity login solely because a source credential changed.

composition requires every generic inner edge to carry an actual category-47 Run
witness. Instantiate edge with actual predecessor Step and one-step Run; do not replace
its native authentication/currentAllows/durability predicates with True. credential_retained
and first_key_retained use the actual ancestor theorems. Financial composition retains
safe handoff, initialized original caller/publication/custody/account prefixes and the
original sourceReady-to-OriginalReady binding. No credential proof creates a reservation
refund or discharges these initialization/IO premises.

Native durable covers the complete conditional event, authentic command/proof references,
projection joins and independently accepted outer prefix. It is not fsync alone. Coherent
rollback of every source, assignment and projection can satisfy all pure joins. A restored
map is not an arbitrary admitted initial state; reconcile the accepted prefix before any
absence/read certificate or CAS. Native counters and canonical namespace encodings must
reject exhaustion/reuse. Safety is conditional; key-loss migration and liveness are not proved.

* Quint execution and counterexample scope
Forty-two deterministic controls import fifteen complete ancestor transition modules.
Only the forty predecessor run declarations are omitted. Official parsed IR comparison
checks every ancestor non-run declaration and the entire current raw leaf. Full official
type/effect analysis is performed once; each test group uses official runTests with a
fresh evaluator and RNG. Typed AST, lookup table and collected definitions are fingerprinted
and must remain unchanged after every group.

Thirty-six guarded controls exercise configured authority, shared workload rejection,
issuer/tenant/producer confusion, full proof, immutable enrollment assignment, current
subject/producer rotation, same-assignment renewal, new-issuance revalidation, lost replies,
current recovery and actual first-key/custody activation with the original hold. Five
unsafe faults inject a forged identity authority, changed enrollment key, erased assignment,
missing publication outcome and phantom outcome. The quarantine control refreshes both
raw child and outer read coordinates on a split image, records the defined pre-rejection
state, then requires new issuance to fail. No successor state is claimed after terminal fail.

The fixture has one original canonical task and a shared workload. Trusted source/peer
assignments and proof/policy booleans represent authentic native verifier results, never
caller-controlled flags. It does not execute Cedar, an IdP or cryptography. The unchanged
predecessor fixture admits a fixed subject authentication key; key migration before an
assignment is described by the general Lean/native contract, not claimed as newly tested
native/public-key support. Same-key subject renewal and producer-key rotation are executed.
Existing-credential retention and budget composition are general Lean properties; the
positive Quint scenarios are focused corresponding observations, not native account tests.

A successful intermediate forty-control run is retained separately in
before-fresh-credential-controls. The final forty-two-control run adds explicit
rejection of a copied public generation without a current credential, and retention
of an already-issued credential through normal identity renewal.

A subsequent review found that current approval alone could conceal a missing
per-call identity proof at issuance. before-per-issue-identity retains that earlier
model and its receipts; the final model adds verifyNewIssue and executes a control
with a current renewed approval but missing fresh caller credential, which must fail.

The first Quint draft reused reserved built-in names assign/next and failed official
name resolution with QNT101. Its source, invocation and parse errors are retained in
draft-reserved-names and are not acceptance evidence. Current successful receipts are
kept separate. The first receipt decoder also encountered stale numbered ITF files
from the intermediate run. Those old traces are retained in its archive; the current
directory is checked against the exact final test/group trace names, and the failed
decoder diagnostic is retained separately. No exhaustive exploration, new random simulation, liveness, native identity/
storage/SDK qualification, performance result or remote CI result is claimed. Ancestor
proof receipts are source-identity reuse, not a fresh rebuild or rerun of every ancestor.
