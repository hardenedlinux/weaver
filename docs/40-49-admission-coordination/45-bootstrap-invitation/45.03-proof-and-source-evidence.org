* Lean quantification and assumptions
The leaf has nineteen printed declarations checked for absence of sorryAx.
Functions indexed by Nat and inductive Run support arbitrary finite invitation
and message populations and arbitrary finite traces. There is no two-worker
bound in these Lean results. The Quint fixture is bounded separately.

Covered states relate every issued ticket to an exact consumed outcome.
SpentBound relates every consumed outcome to the immutable registered ticket.
Their initial assumptions hold for empty issuance/consumption registries; a
restored nonempty image requires a trace-derived accepted prefix, not arbitrary
maps that merely look well formed. Producer provenance starts from an empty
invitation registry and propagates through actual registration events.
new_issue_has_bound_consumption exposes Ready, the complete frozen ticket,
same-event consumed outcome, and unchanged active custody. The credential in
Ready includes native verification and exact key/session/workload equality.

The generic edge in the outer proof is intentionally not declared trustworthy.
composition requires a witness mapping every such edge to the actual predecessor
Run. Instantiate it with the actual LlmIncarnationIssuance.Step and the one-step
Run constructor. That predecessor retains launch authorization, exact signature
verification, freshness and full pre/post durability contracts. Non-consume
outer transitions preserve the issued map. No inner commit can be independently
published before the full outer durable event.

The two financial theorems call the predecessor results with the composed run,
actual initialized caller/publication/custody/account prefixes, Safe handoff,
and sourceReady-to-OriginalReady binding. Unknown source use is explicit.
A pure invitation invariant does not prove a financial invariant without those
premises. The two matching Quint assertions are a concrete retained-hold fixture,
not a replacement for the Lean account-prefix argument.

Native signature unforgeability, independent producer/key assignment, transcript
encoding, confidentiality, session authenticity, durable atomic publication,
anti-rollback floors and implementation refinement are unproved owner premises.
Neither formal language proves physical process isolation, HSM behavior, provider
exactly-once delivery, fairness, or eventual completion. A cloned assigned key or
a relayed authorized signing oracle is outside the bearer-only forwarding result.

* Quint controls and fault interpretation
The current source contains nineteen guarded controls and four fault controls.
It imports the actual predecessor issue, proof, activation, revocation and crash
actions. Its two-ticket fixture retains the original claim/reservation and shared
workload, but gives each intended recipient a distinct assigned key/session.
The assignment oracle is trusted producer input. The duplicate canonical launch
test also encounters its restrictive assignment oracle; it does not independently
qualify a native multi-key uniqueness index. Lean launch retention and actual
registration guards express the general property.

- Bearer-only issuance bypass: an unsafe action calls predecessor issue without
  outer consumption. It creates a pending ticket without a consumed outcome;
  it does not demonstrate stolen-key possession, active custody or a provider send.
- Lost consumption record: delete the outer consumed record while retaining the
  issued ticket. Coverage fails; the guarded recovery protocol never does this.
- Split commit: mark consumed with the wrong result while issuance is absent.
  SpentBound fails; a separate spent write is not an implementation of the CAS.
- Replaced binding: mutate a registered assignment after consumption. Exact
  outcome-to-assignment binding fails even though the old issued result remains.

Decoded traces additionally check the actual predecessor source/account fixture:
no provider source call, original unknown hold retained, floor log unchanged,
and no active incarnation change for these four pending-issuance faults.
The guarded activated initializer separately exercises the actual custody change.
No fault test treats a missing local response as proof of failed execution.

* Bounded execution and historical failures
The initial all-control route reached its fixed 55-second watchdog. A narrower
single-control diagnostic was manually interrupted and is not acceptance evidence.
The first four-control recursive-import route also reached 55 seconds. Explicit
types were then added, and the retained-hold assertion strengthened. Two recursive
parse routes reached their 20-second limits. An all-control bundled test reached
55 seconds as well. All these diagnostics are retained, not counted as passes.

The accepted route bundles the thirteen existing modules into one file, removing
only local import source paths while retaining module names and aliases. It then
partitions only current run declarations into six disjoint groups. The official
parser accepts the bundle. All twelve ancestor non-run declaration IRs match the
sealed parent IR; the official phase-one parser's complete current leaf matches
the bundle IR after checking its top-level lexical depth zero. Only parser IDs,
import file paths and declaration order differ. Bodies, types and effects remain.
Each retained test source span is unchanged and all twenty-three tests occur
exactly once across the groups. The raw current leaf in quint-core remains
byte-identical to dev/proofs/qunit. No watchdog is enlarged. This changes input
organization and scheduling, not the transition relation or invariant.

The simulation bundle omits only already-covered current run declarations and
preserves all transition and invariant source. Its consumed-state exploration
reached the original 30-second watchdog. No randomized sample is admitted as a
current pass, and the activated-state exploration was not dispatched after the
failure. Targeted tests and arbitrary-finite Lean proofs are distinct evidence;
there is no current exhaustive-state or liveness claim. Requested exploration
parameters and seed remain in exploration-commands.json.

The thirty-one predecessor controls have separate sealed passing receipts; their
source and closure identities are freshly checked and those receipts are reused,
not described as a current rerun. Thirty-one earlier Lean source hashes, successful
logs and compiled artifacts are also checked before reuse. Native qualification
and remote CI are not claimed.
