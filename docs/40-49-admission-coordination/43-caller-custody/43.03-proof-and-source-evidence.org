The Lean relation wraps actual category-42 publication events. Metadata events may
only preserve its journal. Determining events require a native Permit and append
the capability projection in the same transition. Worker permits preserve the
current grant; rotation requires old-key proof and new-key enrollment, clears the
actual inherited join/resolution, and retains original scope; handoff requires an
authenticated independent recovery principal, fresh incarnation and increased
fence/serial. The modeled issued-incarnation list is protected state, not a cache.

Twenty-two printed declarations are checked without sorryAx. Scope, serial, trusted
time, issued identities and publication refinement cover arbitrary finite runs.
The final-floor worker theorem requires aligned current custody, established by fits_run; the
original-result and account theorems explicitly require initialized publication,
custody and account prefixes. Budget results retain Safe handoff and authentic
original reservation/source binding premises; they do not follow from identity
checks alone. An unknown source remains unmetered under that binding.

Quint uses the actual predecessor armed fixture and actual inherited floor/account
transitions. It has two staged command slots, two worker incarnations sharing one
workload principal, old/new keys and a distinct recovery context. Reconnect channel
identity differs from incarnation identity. Rotation adds an explicit protected
custody restart event because the predecessor Quint command table has no restart
command. It uses actual C.restart, current P.ready/parent checks and P.noted; it
does not call resolve or fabricate a new floor outcome. Lean expresses the same
restart through an actual P.Step. The two representations have separately checked
properties; no automatic Quint-to-Lean refinement theorem is claimed.

The final leaf-only Lean refresh strengthens the caller/join theorem to expose
the actual current custody, joined source proposal and exact original outcome
in its statement. It changes no transition or Quint input; 29 unchanged compiled
ancestor receipts are hash-checked before retaining them, and the leaf source,
compiler log and command receipt are refreshed.

The original semantic commitment is carried by the inherited publication envelope;
the focused Quint grant has a fixed canonical domain and inherits the original
proposal fixture. Lean stores the full original proposal in the grant. Arbitrary
protocol/domain namespace integrity and cryptographic commitment collision
resistance remain native/semantic-owner premises, not conclusions of this finite
fixture.

* Counterexamples and interpretation

| Mutation control | Actual failure observed | Evidence boundary |
|------------------+-------------------------+-------------------|
| sharedIdentityCallerCounterexampleTest | A command naming the new holder/fence commits an actual floor record when peer binding is bypassed | Qualification monitor is false; original source provider-call count stays zero |
| expiryCallerCounterexampleTest | A staged request commits after its grant deadline if final peer/deadline binding is bypassed | Actual floor append, not an external provider send |
| splitGrantCallerCounterexampleTest | Actual custody/log handoff advances fence while the grant projection remains old | Alignment fails; no claim of a second floor append |
| workloadMintCallerCounterexampleTest | A restored old worker substitutes its incarnation/key in the capability without a protected event | Exact last-envelope capability alignment fails |
| redeliveryRenewCallerCounterexampleTest | Redelivery silently extends the deadline | Immutable scope/envelope check fails; no account refund is performed |
| restartReuseCallerCounterexampleTest | Recovery forgets issued incarnations | Non-reuse state fails; does not claim an actual duplicated floor record |
| rotationOldKeyCallerCounterexampleTest | Old native key can publish a custody resolution event if key binding is skipped | Deliberate authentication-monitor violation; floor count remains unchanged |

The bypassCaller fault deliberately omits a peer argument and authentication
check, representing an unmediated endpoint callable by the fixed old peer. The
decoder independently confirms that the current incarnation/key or deadline
would reject that peer. Its ghost flag marks the omitted check; it does not
authenticate an attacker from native transport evidence.

All seven fault actions are outside the guarded step relation. Their exported ITFs
are independently decoded, including actual custody/floor changes, grant/log
alignment, original reservation hold and unchanged provider execution. Ghost
qualification failures are distinguished from real inherited floor appends.

* Reproduction and evidence limits

Run the focused checker (retired Python driver). It compiles thirty Lean modules, checks twenty-two new
printed declarations, typechecks Quint, runs twenty-seven new controls and seven
exported mutations, samples eight initializers with ten samples and up to thirty
post-initialization steps each, and regresses the predecessor's twenty-five
publication controls. This is finite randomized exploration, not exhaustive model
checking or runtime fault injection.

The final receipt distinguishes semantic verification from the standalone resource
gate. A standalone typecheck timeout is never reported as a passing command, even
when the official test pipeline successfully typechecks the same executed source.
After a retained timeout, =--resume-models --reuse-typecheck-timeout= validates all
unchanged compiled-module hashes and the exact timed-out Quint input before
continuing with fresh tests. It does not reuse a successful typing verdict from
a failed command or increase any watchdog.

The first full-import parse reached its unchanged twenty-second watchdog. Five
later compact typechecks also reached that fixed watchdog; all failed receipts
are retained. An Org export overlap did not explain the later failures. Selective
imports remove a redundant whole custody namespace. The accepted execution plan
uses explicit helper types and keeps the negative-control qualification flag as
a ghost monitor rather than embedding another full authorization expression in
its state update. The independent decoder checks the concrete incarnation/key
or deadline mismatch for the fixed old peer used by those fault injections. It
also separates current controls from predecessor controls instead of typechecking
both sets on every focused run. No watchdog is enlarged. The standalone twenty-second typecheck remains a
failed resource gate. The installed official CLI test pipeline performs load,
parse and typecheck before running tests; its source hash and exact pipeline
line are recorded separately. A passing test route supplies semantic typing
evidence, not a retroactive pass for the timed-out standalone route.

The current closure omits only 356 ancestor run declarations using freshly
hash-checked predecessor parser/source-map receipts. All retained ancestor
transition/type/helper declaration IR is independently rechecked, including effect
qualifiers; only parser IDs and declaration ordering are normalized. The new leaf
source is byte-identical to its executed copy and retains all 27 controls. The 25
predecessor publication controls run separately against their existing sealed
closure; its source/core hashes are freshly checked, and its publication source
is byte-identical to the raw predecessor. These are two qualified execution
closures, not a claim that all ancestor tests execute in the new leaf. No other
omitted ancestor tests are claimed rerun.
