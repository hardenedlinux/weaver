* Lean premises and composition
Thirty-two printed declarations are compiled with no sorryAx. Registries are indexed
by Nat and Run is inductive, covering arbitrary finite populations and traces.
Valid binds each credential to its immutable Plan, authenticated peer transcript,
canonical launch and unique ID index. Requested and Released bind signing stages.
Joined and Outcome constrain both directions of actual predecessor root activation.
qualified_step and qualified_run derive preservation from constructor guards and
append rules; they do not assume the entire post-state invariant as a premise.

plan_origin derives independent producer assignment from an empty initial Plan
registry. issuance_authorized uses the retained Plan and Valid relation. Native
planAuthorized cannot be implemented as a shared-SA check. verifyIssue authenticates
both subject-key and enrollment-key proofs for the full body; verifyUse authenticates
a fresh bootstrap holder transcript. signature covers exactly the committed body.
They are distinct predicates, not interchangeable booleans in an implementation.

Current adds live credential and predecessor epochs, original Blueprint, current
revision, authentic current policy and qualified image to historical joins. A
revocation advances both outer issuer and actual predecessor enrollment epochs.
The predecessor propagates the downstream invitation-issuer fence. Historical
rows remain valid provenance; current usability is a separate condition.

composition requires every generic inner edge to have an actual category-46 Run
witness. Instantiate it with category-46 Step and a one-step Run, retaining its
native rootAuthorized and durability premises. first_key_retained applies actual
category-46 no_replacement. Financial theorems apply its actual original account
uniqueness and unknown-hold theorems with initialized caller/publication/custody/
account prefixes, safe handoff and original sourceReady-to-OriginalReady binding.
No initialization, authentic-facts, original-budget or native-durability premise
is discharged by a credential signature.

A recovered arbitrary map is not a reachable initial state. Pure qualification
cannot detect a coherent rollback of every table and ID counter. The independent
accepted-prefix premise must include the entire outer enrollment history. Restore
below that prefix is rejected before any absence/read certificate or mutation.
Nat counters do not wrap; bounded native counters must reject exhaustion. Neither
key-loss migration nor recovery liveness is proved.

* Quint controls and counterexamples
The new leaf has forty deterministic controls over two canonical launches, two
independent subjects and one shared workload. It imports fourteen complete ancestor
transition modules. Parent run declarations alone are omitted; official parsed IR
comparison checks every non-run ancestor declaration and the entire new raw leaf.
Full official type/effect analysis occurs once. Each group executes through the
installed official runTests with a new evaluator and RNG; the typed AST, lookup
table and collected definitions are fingerprinted before/after each group.

Thirty-four guarded controls exercise current policy/proof requirements, distinct
IDs, lost replies, signer recovery, stale callback rejection, actual root and
beneficiary/invitation/custody activation, retained unknown hold and issuer fencing.
Five unsafe injected faults show forged subject facts, lost credential/release,
missing activation outcome and phantom outcome. A sixth quarantine control first
refreshes the raw predecessor read on a split image, records the fully defined
pre-rejection state, then requires the outer bind action to fail. No post-state is
claimed for a failed action. Faults are outside legal step; they are not security
failures of the guarded transition relation.

The fixture proof booleans and authenticated channel assignments are trusted native
results, never caller-controlled request flags. They do not execute Cedar or a
cryptographic verifier. new_root_stages_only additionally fixes the entire successor
predecessor state to the exact root/revision update; new_root_has_current_holder
extracts the current released credential and fresh holder proof for every new root.

The fixture uses preallocated placeholder map keys for the two credential IDs,
with a separate authoritative allocated-ID set. Placeholders grant no ownership;
Lean uses arbitrary Nat-indexed optional maps. The first draft used Map.set on an
absent key and produced QNT507; that tool/model error and its failed invocation
are retained in draft-empty-map. It is not counted as a passed security control.
The initial Lean draft diagnostics are likewise retained in lean-initial.log.

Current evidence is focused deterministic model execution and conditional Lean
proof. It is not exhaustive state exploration, new random simulation, native
crypto/storage/SDK testing, recovery liveness, performance qualification or remote
CI. Predecessor receipts are source-identity reuse, not fresh execution of all
historical controls or compilation of every ancestor this turn.
