* Decision and scope

The journal, recovery image and actual final-owner admission now share one
reachable product in [[file:../../dev/specs/lean/ComposedGatewayLifecycle.lean][ComposedGatewayLifecycle.lean]]. Its initial journal contains the
empty finite ledger. Ordinary payload publications use the existing finite
ledger transition relation; migration decisions preserve that exact payload.
The product adds operation-bound sealing, immutable terminal decisions,
commit-bound activation, owner incarnation changes, persistent range delegation
and possibly delayed exposure. This extends the conditional component join in
[[file:19-anchor-recovery-and-egress-contract.org][the preceding contract]] without rewriting its historical results.

The composition is an abstract safety proof. It does not implement a journal,
prove storage durability, authenticate an actual owner, refine a driver, or
establish a database/socket atomic operation. An independent authenticated,
non-equivocating journal and a qualified durable transport owner are premises.
The transport owner's persistence must cover its own restart, not only host
rollback. Missing or unverifiable owner state keeps admission unavailable.

The checked range unit is one bounded application exposure per canonical
message, subordinate to an already journaled complete-message offer. It is not
a second complete-message offer, an arbitrary sequence of chunks, a TCP packet,
or a provider business effect. Multiple ranges need an immutable message/range
manifest, range-specific quota and a finite-sum extension; allocating a new range
ID after uncertainty is forbidden under the present one-range contract.

[[file:../../dev/specs/quint/ComposedGatewayLifecycle.qnt][The Quint product]] starts with four already admitted canonical messages,
two shared weighted accounts and fixed claim bindings. This is an executable
post-admission fixture, not the Lean empty initializer. Lean covers arbitrary
finite keys through its actual imported finite ledger. No machine-checked
Quint-to-Lean or owner-source refinement is claimed. The Quint fixture keeps
lineage and admitted identity/cost projection fixed and summarizes full recovery
with those fixed fields plus current head/history. Lean retains the full payload
and lineage equality. Neither abstraction proves cryptographic authenticity.

The finite Config is an authoritative semantic identity/account mapping fixed
for this lineage. Starting a new process, namespace or Authority cannot select
a new Config and fresh empty initial state for the same original intent. Such a
new product instance is not an allowed recovery transition. Scheme admission
and authenticated anchor membership must resolve the original canonical domain;
that identity resolution remains a source/refinement premise, not a proof about
arbitrary caller-created copies of this model. [[file:../../dev/specs/evidence/composed-lifecycle-2026-10-19.org][The receipt]] records checks
and bounds separately from the physical acceptance obligations below.

* One protocol and its linearization boundaries

1. Scheme resolves the canonical operation, message, budget/history roots,
   immutable subject and policy/source context. Rust accepts only the exact
   admitted request. Go retries observation of that same operation.
2. The actual owner atomically closes admission and stores the complete seal
   request. The seal binds operation, expected journal predecessor, lineage,
   source epoch, target and semantic binding. An acknowledgment is returned only
   after this closure and record survive the selected restart fault model.
3. The journal decides that same request once using predecessor CAS and its
   operation registry. Commit retains the complete payload and advances the
   transport epoch; abort installs a terminal tombstone without advancing it.
   Neither a new command ID nor another migration can consume the first seal.
4. Recovery reads the authentic complete current head, not a cached success.
   Activation checks the same sealed request, stored committed receipt, exact
   current receipt/head, source-to-target epoch and current owner incarnation.
   Activation clears the seal and opens only that successor epoch.
5. Before irreversible delegation, the owner checks the recovered authoritative
   state, current original executor ticket, original claim/token/stream, held
   reservation, already admitted message offer, restrictive account history,
   current owner epoch/incarnation and absence of a durable range record.
6. The durable delegation record is the no-replay point. It precedes the external
   transport call. A crash before or after the call produces a possibly-exposed
   range, never a fresh send opportunity. This deliberately permits conservative
   loss. It cannot promise delivery or exactly one physical transmission.

The selected conservative profile serializes seal with all protected payload
publications and actual delegation at the external owner. Pending migration
pauses new payload publications. A handoff that wins first remains a durable
possible exposure; a seal that wins first blocks new handoff. Two seal requests
cannot both own the same source epoch. The second must resolve the winner and
obtain a separately admitted migration after the first closes.

The finite ledger's executor/domain fence and the product's transport epoch are
different coordinates. Moving a transport endpoint does not change canonical
budget/history roots or transfer a claimed executor. A worker-generation or
domain-fence change still invalidates the old finite ticket. A replacement owner
may reconstruct an opaque handle only after full current validation of the
original claim; it cannot retag a previously delegated buffer or resurrect a
claim whose original executor is no longer current.

Pausing publication is a safety baseline, not a required global mutex across
unrelated roots. A sharded implementation must prove an equivalent complete
conflict/dependency closure. If revocation must take effect while migration is
pending, a separately proved cancellation/barrier protocol is needed. The
current model does not silently admit such a path or guarantee its latency.
Abort remains sealed; no timeout-based reopen or abort-to-success transition is
modeled. Administrative recovery requires a separately admitted protocol that
preserves the terminal operation and all existing obligations.

* Concurrency, response loss and restart matrix

| Schedule or observation | Required behavior |
|-------------------------+-------------------|
| Two seals race at one epoch | The owner durably chooses one complete request; loser gets conflict/unknown and cannot submit its request under the winner's seal |
| Seal wins before delegation | Old handle is rejected at the actual writer gate; cached preflight is irrelevant |
| Delegation wins before seal | Range remains accepted/possibly exposed and cannot replay; later seal does not retract old buffers |
| Seal response lost, owner restarts | Recover the durable same seal; never infer open from missing volatile acknowledgment |
| Commit response lost | Resolve the original canonical operation and full binding; new RPC command cannot append again |
| Fresh lookup has no record | Request can still be in flight; retain pending state; only a terminal abort tombstone excludes a late commit |
| Abort response lost, delayed commit arrives | Same operation is already terminal; delayed commit is rejected |
| Commit succeeds while owner is restarting | Durable seal remains valid; owner remains not ready until authentic full recovery; activation uses its current incarnation |
| Activation response lost | Query the actual current owner state and original committed transition; retry is a status resolution, not a second opening or new handle |
| Old activation reply arrives after another owner restart | Reply has historical incarnation; it cannot set ready/open or authorize a current handle |
| Restart after delegation, before response or transport call | Durable range record survives; no replay even if actual exposure was zero or cannot be observed |
| Restart while kernel/driver/remote buffers survive | Old buffers remain possibly exposed; recovery does not infer retirement, exact prefix or safe tail reuse |
| Anchor unavailable after delegation | Reject new protected admission; previously delegated buffers may drain |
| Partial or stale owner-store restoration | Fail closed; a current head number with empty range records is not complete recovery |
| Owner store and its only anchor roll back together | Outside the qualified premise; require separate durable high-water/commit membership or remain unavailable |

The logical append of a delegation record and a socket write are not atomic.
The qualified owner must serialize seal with the irreversible writer delegation,
and must not enqueue an unrecorded callback that can escape that serialization.
Recovery verifies the owner-store prefix containing every possibly delegated
range, alongside the authoritative journal payload. The model keeps these two
stores distinct; journal recovery alone does not reconstruct missing range
records. Its owner-restart transition preserves the durable owner store by
premise, and recoverOwner does not admit arbitrary replacement owner images. If that
prefix cannot be established after a torn write, preserve an uncertainty
fence over the affected scope. Do not rebuild an empty accepted set.

An external owner's restart does not prove old instances or helpers stopped.
The storage/driver ownership protocol must exclude an old process still holding
a raw FD, copied send buffer, asynchronous callback or NIC offload descriptor.
A numeric incarnation in a new process is insufficient. The new instance may
open admission only when the actual delegation gate rejects old incarnations;
old accepted buffers remain governed by the weaker possible-exposure contract.
Concurrent replacement instances require exclusive ownership/CAS at that same
gate. These are physical refinement obligations, not consequences of Lean Nat.

Historical admission does not mean a range remains newly admissible after a
restriction. A previously delegated range can drain under its original admitted
image. The trace monotonicity theorem and gate theorem constrain future new
admission, not bytes that crossed the earlier irreversible boundary.

The driver projection carries a unique pending range capability. Delegation
creates it once; drain consumes it before recording the exposure observation.
The pending capability represents original driver/transport ownership, not a
restartable outbox command. Owner restart does not recreate it from accepted
records. The exposure counter is a proof observation and never an action guard.
Uniqueness/non-reconstruction of that driver capability is an explicit physical
premise; copied callbacks, raw FDs or a replayed outbox invalidate it. Deliberate
queue-reconstruction and raw-FD mutants retain counterexamples to that premise.
No claim about duplicate network packets follows from this abstraction.

The no-replay invariant counts actual acceptance transitions rather than using
an overwritten Boolean as the count. The ghost count is never used as a runtime
guard: the real guard is durable range absence. The count remains historical in
counterexamples that erase the owner store. Canonical operation counts likewise
remain independent of RPC command IDs and response delivery.

Financial quantities retain the earlier finite model's meaning. Fixed admitted
cost remains held or charged; outcome alone does not settle, and this product
adds no refund. Actual provider cost, retirement authenticity and unbounded
future accrual remain external evidence obligations. A complete-message offer
in the finite ledger and its later bounded delegation are distinct facts;
this product cannot be read as a proof of arbitrary chunk replay or billing.

* Executable controls and counterexamples

The normal Quint controls exercise lost commit replies across host/owner restart,
competing seal/commit rejection, wrong activation request, fresh-command replay,
terminal abort versus late commit, missing versus abort, restart before commit,
stale activation incarnation, retained delegation, stale handle rejection,
shared-history rejection, stale recovery, and post-migration old-buffer drain.
Additional controls cover seal and activation reply loss across restart,
seal winning against delegation and a fresh nonce replacing the original claim.
The old-buffer drain is a valid witness of the physical boundary, not a normal safety failure.

The seal/receipt-substitution controls use an independent violation observation:
ordinary account/count invariants alone would miss those binding errors. The
mutation deliberately bypasses the exact guard and records that fact. This
shows why the guard matters; it is not a discovery of a bug in existing runtime
code. Full traces and source hashes are retained in the receipt.

* Scheme, Go and Rust obligations

Scheme owns canonical identity, domain/account bindings, Code as Policy
composition, Cedar projection and the semantic admissibility of migration and
recovery. It must reject issuer-, reconnect- or caller-selected aliases that
pretend the original intent is a new empty message/account. It specifies which
source/history dependencies invalidate admission. It does not claim fsync,
exclusive writer ownership or transport cancellation from a pure receipt.

Go owns cloud-native discovery, Kubernetes reconciliation, agent/protocol SDK
adaptation and bounded lifecycle coordination. It preserves the same canonical
operation across retries and reports unknown outcomes. Discovery/route changes
become fresh proposals; they cannot mutate an admitted destination or use SDK
redirect/retry to bypass the broker. Go neither opens raw protected egress nor
clears claims, budget or accepted ranges after a pod/owner restart. Activation
responses are observations scoped to the actual current incarnation.

Rust is the reference owner of canonical journal CAS, complete recovery,
operation resolution, actual delegation serialization, durable range records
and epoch/incarnation enforcement at the final writer. Placement, storage and
driver ownership must satisfy the independent-fate premise. Recovery of owner
state is read/verify/materialize, followed by current owner admission; it is not
a replay loop over old send commands. Cedar evaluation can remain off the per-byte
path only when the immutable bounded manifest and every changing dependency
are checked at delegation with a proved invalidation protocol.

Quint explores schedules and explicit bad designs. Lean proves composition for
the declared transition relation and arbitrary finite ledger. Neither runs on
the request path or replaces real storage, actor-authentication and driver tests.
