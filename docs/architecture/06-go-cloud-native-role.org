* Answer and evidence boundary

Go's role is to make an AI-native gateway an operable network/cloud service:
infrastructure discovery, resource reconciliation, identity integration,
configuration distribution, deployment lifecycle, and potentially selected
network adapters. It need not run an AI agent, implement model reasoning, or
own the policy semantics to provide substantial value.

The inspected agentgateway snapshot uses Go for its Kubernetes/controller and
control-plane integration and Rust for its proxy runtime. That observation is
not an argument that Weaver must use the same placement. The ecosystem rationale
below is an inference from the inspected integrations, not a statement of the
upstream authors' undocumented motives or a benchmark result.

* Code as Policy responsibility

Go makes the policy service operable through Kubernetes/network ecosystem
integration: bounded discovery, authenticated artifact delivery, workload
identity, generation-aware status, and requested drain/replacement. It cannot
turn controller acceptance, a callback acknowledgment, or a Pod deletion request
into policy approval, source admission, physical retirement evidence, or a new
emission handle. The admitted Code as Policy closure and its error behavior
remain the same for a Go connector and a Rust connector. See
[[file:09-code-as-policy.org][Code as Policy]] and the [[file:05-authorization-execution-protocol.org][callback and state contracts]].

* Why Go is a useful fit

Kubernetes resources change continuously: Pods move, Services select endpoints,
Secrets rotate, route references cross namespaces, and backends become ready or
unavailable. Go's controller-runtime/client-go ecosystem provides reusable
patterns for this reconciliation, cache/watch, identity, and status work. The
inspected syncer also uses Istio KRT collections; it is not simply a handwritten
HTTP server. Compatibility and dependency cost still need evaluation.

For an AI-native gateway, the same lifecycle applies to tool servers, model
backends, inference pools, workload identities, and their discovery metadata.
This makes Go useful even when all payload forwarding remains in Rust. An
MCP target appearing in a Service selector is discovery evidence; it is not
permission to invoke that tool.

Go also has a substantial networking/SDK ecosystem. Qualified Go ingress,
gRPC services, provider connectors, and identity adapters remain placement
candidates. Measure their actual streaming, cancellation, allocation, GC, and
integration behavior. Do not demote Go to a controller by language rule, or
assume that cloud-native friendliness proves it should own every hot path.

* Concrete Weaver reference placement

1. Go owns the cloud integration services: observe Kubernetes/infrastructure,
   reconcile operational state, propose scoped endpoint/route updates, deliver
   admitted publications, and report their observed activation/rejection.
2. Scheme owns POO semantic composition, domain Governance, capability selection,
   source-bound assessment and lifecycle transitions. Go submits authenticated
   observations and intent; it does not recreate these meanings in CRD handlers.
3. The reference Rust runtime owns physical durable coordination, strict Cedar
   authority integration, credentialed final dispatch, and their failure handling,
   following [[file:05-authorization-execution-protocol.org][Authorization-to-execution coordination]].
4. A selected Go or Rust protocol adapter produces the frozen request. A Go
   adapter that actually emits credentialed traffic becomes a qualified final
   broker with the same obligations, not an exemption from the Rust reference path.

This gives Go a concrete first responsibility while keeping network placement
evidence-driven. Standalone Weaver can omit Kubernetes reconciliation and use
the same publication/authority contracts. A Kubernetes installation does not
need to import a second agent orchestration framework merely to use Go.

* Go interfaces: operational control without ambient send authority

Go's initial placement is a first-class control and integration plane, not a
requirement to implement an agent reasoning loop. An AI gateway must keep tool
servers, model endpoints, identities and routes operable as cloud resources
change. Reusing Go's ecosystem for that work avoids rebuilding the surrounding
cloud platform inside the policy kernel.

| Go boundary | Input and output | Consumer and authority limit |
|-------------+------------------+------------------------------|
| Infrastructure observer | Scoped watch events become endpoint/route proposals with tenant, provenance and freshness | Scheme/source owner assesses semantic eligibility; runtime activates only admitted scope |
| Identity integration | Authenticated workload/issuer/audience facts with their expiry and acquisition context | Authority binds the exact actor/delegation; authentication does not imply permission |
| Publication transport | Owner-admitted closure and dependency set delivered to named runtime instances | Runtime validates activation and rollback constraints; Go reports actual observed status |
| Protocol adapter | HTTP/gRPC/MCP/provider input becomes one immutable operation and bounded payload reference | Authority/coordinator receives the exact action, recipient, payload and obligations |
| Lifecycle operator | Scoped drain/replacement intent and observed health | Physical owner retires or fences capabilities; controller cannot declare an old emitter stopped |

These are logical service contracts, not new RPC implementations or a selected
serialization library. Preserve the existing POO owner interfaces and extend
only their identified missing contracts. Endpoint proposals, identity facts,
policy publications and frozen operations must not share an untyped
configuration channel that lets a controller accidentally issue authority.
An operational constraint may narrow an admitted route; widening it requires
fresh owner admission.

** An agent tool call through the reference placement

Go discovers candidate tool backends and integrates the caller's workload
identity. Scheme selects the applicable Governance closure and supplies its
source/lifecycle contract. A Go or Rust adapter freezes the specific tool
operation. The Rust authority evaluates the required Cedar checks, and the
coordinator consumes the grant, commits history/budget obligations and claims
one attempt. Only the constrained broker can redeem that claim for the bound
credentialed upstream operation. Returning a tool result crosses a separate
response-release boundary.

An SDK convenience call cannot occur between discovery and that broker as an
unrecorded shortcut. A Go connector either hands off the complete frozen
operation without unrestricted application credentials, or is explicitly
selected as the final broker and assumes the same isolation, claim and transport
contract. Its provider SDK must expose control over retries, redirects, token
scope, connection identity and streaming behavior. If those controls cannot
preserve the contract, that connector is unavailable for the protected profile.

** Watch loss, update churn and control-plane outage

Watches and reconciliation are asynchronous. Queue coalescing may reduce work,
but cannot erase an ordered revocation or label stale observations as current.
An endpoint replacement cannot mutate an already authorized operation. It must
satisfy that operation's admitted destination constraints or start a newly
admitted operation; frozen intent does not mean blindly using a stale endpoint.

If Go's control services are unavailable, the data path may use only a still
valid admitted closure and source/identity leases whose contract explicitly
permits that independence. Required freshness that cannot be established blocks
admission or the applicable checkpoint. There is no unconditional cached-allow
or last-known-good permission mode. A restarted controller reobserves state;
it cannot restore a spent claim or turn an unknown send into an absent effect.

Keep watches, joins and status fanout outside the per-operation serialization
section. Reuse bounded connection pools and immutable admitted artifacts where
their currentness contracts allow it. Request-time identity/source checks that
are mandatory remain explicit costs, even when their integration is Go-owned.

* Deep adapter-to-broker contract

The focused [[file:13-go-adapter-broker-boundary.org][Go adapter to Rust broker review]] defines exact SDK construction/handoff,
application-start multiplicity below client APIs, immutable message/range staging,
route/connection identity, credential release and conservative unknown outcomes.
Its [[file:diagrams/14-adapter-broker-boundary.svg][core boundary view]] makes the constrained submission path explicit. Go
control-plane integration does not grant the adapter an upstream network path;
SDK plugins and background work cannot inherit such authority. Retried internal
RPCs resolve the same bound command; they do not retry the external effect.

* Streaming producer limits

The selected [[file:14-stream-message-authorization.org][message-stream profile]] keeps Go's assembly/staging bounded and inert.
Rust verifies complete immutable messages, holds parent-backed credits before
queue eligibility and owns the stream writer. Multiple Go producers cannot
convert their local queue or a Session pending list into budget or dispatch
rights. The one authorized message slot per stream preserves P15's finite
synchronous lifecycle reuse; independent streams can still run concurrently.

* Cloud-native state versus execution authority

| Cloud observation or mechanism | Permitted conclusion | Forbidden conclusion |
|--------------------------------+----------------------+----------------------|
| TokenReview succeeds | Peer has the validated workload identity/audience | It may issue grants, change another tenant, or invoke arbitrary internal RPCs |
| Controller wins leader election | It may perform its delegated reconciliation role | Old dispatch workers are fenced or an effect may be replayed |
| Route Accepted / Programmed | Controller/proxy reports the named resource state | A particular operation passed Governance and authorization |
| Service endpoint becomes ready | Endpoint is a candidate within an admitted backend scope | Endpoint inherits secrets/capabilities from any matching label |
| xDS ACK or push completes | Delivery/acceptance observation for a resource version | All dependent closures or all replicas are active and current |
| Metrics show low token spend | An observed usage sample exists | Global budget has free capacity or unknown requests were uncharged |
| Pod rescheduled | A new worker may request its own scoped identity | Old claims, grants, history, or uncertain effects are reset |

Kubernetes leader election is not a fencing protocol for arbitrary network
effects. Runtime claim/fence and the no-redispatch rule survive controller or Pod
replacement. Readiness must reflect actual qualified runtime dependencies;
it cannot override an expired issuer lease or incomplete recovery state.

The concrete source/ledger/fencing contract is in
[[file:07-source-admission-ledger-fencing.org][Source admission, durable ledger, and fencing contracts]]. Go requests a
supervised replacement under its delegated role; it does not choose the ledger
fence, recreate owner-issued source handles, or clear a spent dispatch claim.
It reports quiescing/unknown when physical retirement is unproven, rather than
turning controller convergence into a stopped-old-worker assertion.

RBAC and workload identities should be role-specific. Separate discovery reads,
status writes, publication proposals, publication signing, runtime admission,
and credential access. A controller that watches Secrets or mutates Deployments
has a material trust role; minimize that scope and include it in the compromise
model. Preserve namespace/tenant provenance across translations, label selectors,
ReferenceGrant handling, service discovery, and workload identity validation.

* Performance and validation implications

Keep resource watching, large joins, translation, and status publication outside
the request's admission/dispatch critical section. Coalesce safe update work,
but never merge away a revocation or report old state as current. Bound queues,
staging memory, fanout, stale watch intervals, and resynchronization after loss.

Evaluate Go's value along two independent dimensions:

- Integration quality: correctness under watch restart, version skew, secret
  rotation, endpoint churn, permissions, status generation, and tenant isolation.
- Network-path quality, when selected: full protocol conformance, equal strict
  authorization/coordination semantics, streaming behavior, resource use, and
  failure containment compared with the Rust candidate.

Source inspection does not yet choose an upstream library embedding API, a
specific Kubernetes version, an Agent SDK, or a Go proxy implementation. Record
the actual benefit and maintenance owner before adding those dependencies.
