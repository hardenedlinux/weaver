* Scope

Praxis is a Rust filter framework with a separately released AI gateway.
Agent Gateway provides a unified proxy for inference, MCP and A2A, with a
Kubernetes control plane. Weaver concentrates on the authorization and
accounting of an original task from source publication through provider send,
stream delivery and recovery. Compare the boundary each product enforces and
the integrations it ships.

* Architectural decisions and their consequences

** Configuration, publication and authority

#+begin_example
Weaver
  authenticated source -> durable intent + barrier -> Scheme/POO derivation
       -> version-checked publication -> Rust authority + reservation
       -> bound provider send -> qualified range -> final receiver cursor
       -> attributed release -> Scheme derives the next eligible step

Praxis Core / AI
  YAML -> validate + build filter pipeline -> publish candidate chain
  HTTP -> classify / normalize -> configured request and policy filters
       -> router / filtered upstream attempt -> response and body filters
       -> client response; configured metering reconciles usage

Agent Gateway
  local YAML/JSON ---------> shared runtime IR <- xDS <- Gateway API controller
  HTTP / MCP / A2A -> listener and route -> attached policies -> backend
       -> per-attempt and response processing -> client / telemetry
#+end_example

In Weaver, a valid compiled object is a proposal until publication verifies
the exact source cut and intent. Go carries observations and proposals between
systems. The Rust owner retains the durable decision and controls the actual
effect. An A→B→A change can produce the same apparent configuration while
belonging to a different authority epoch. Explicit identity and the barrier
give the receiver a basis to reject work captured under the earlier A. The cost
is a stateful publication protocol and a temporary loss of availability for
affected work while the outcome is unresolved. This trade matters when a source
change withdraws permission with operational consequences.
[[file:../../dev/sysml/ControlActivation.sysml][Source activation model]]
· [[file:../../crates/ledger/src/publication_barrier.rs][Durable intent]]

Praxis AI validates and builds candidate chains before it swaps the applicable
live pipelines. Candidate rejection preserves service with the prior
configuration. That is a useful failure boundary for traffic operators who
need predictable configuration rollout. Some topology and protocol changes
still require restart. A chain swap answers which configuration handles
traffic. Cancellation of an already granted external action requires an
additional contract that specifies which generation owns that action.
[[https://github.com/praxis-proxy/ai/blob/f96d0114a995765793b1fb33f86f94ecc298eb08/server/src/reload.rs][Reload implementation]]

Agent Gateway reduces control-plane fanout by mapping user-facing resources
closely to xDS and by making child resources reference parents. A route change
can publish a route resource instead of rebuilding the whole parent list.
Policies retain their attachment and merge at runtime. This favors Kubernetes
integration and incremental distribution. The proxy pays for attachment and
merge semantics, and operators need the effective policy to diagnose conflicts.
The useful pattern for Weaver is small, independently addressable publication
units with explicit dependencies. Activation of an affected unit must still
respect Weaver's original authority and shared-domain fences.
[[https://github.com/agentgateway/agentgateway/blob/134897e1975fa26fa5c5b8ba45d720d05d3f7fb8/architecture/configuration.md][Resource cardinality and policy merging]]

** Policy, extension and trust boundaries

Weaver gives Scheme ordinary programming and relational derivation over typed
POO objects. This lets one semantic layer express both source impact and
workflow eligibility. Cedar then evaluates current, schema-bound facts at the
effect boundary. Rust checks and consumes the ledger state that the decision
depends on. Keeping these roles separate limits what an extension can authorize
by returning a value. It adds integration work across the typed C ABI, Cedar
inputs and durable transitions, and it requires a clear ownership rule for
changes that span those interfaces.
[[file:../../scheme/gateway/func.ss][Scheme derivation]]
· [[file:../../crates/policy/src/authorize.rs][Cedar decision]]
· [[file:../../crates/ledger/src/provider_admission.rs][Native admission]]

Praxis APL can put transformation, credential delegation, approvals and PDP
calls in one ordered chain. That makes policy changes practical when the
operator wants to insert a filter at a known phase. The resulting authority
depends on phase ordering, trusted inputs and plugin behavior. The central
review question is which policy sees the final bytes and identity after all
mutations. Reusing an APL phase model or plugin contract can clarify Weaver's
adapter extension points. Importing a second policy language for the same
governance decisions would also introduce two sets of precedence and failure
rules to qualify.
[[https://github.com/praxis-proxy/policy/blob/828cb41c2f31723445c4e31051b44f59afa2f53f/docs/content/apl/effects.md][APL effects and ordering]]

Agent Gateway makes CEL predicates available where proxy state is observed,
with distinct policy contracts for requests, responses and backend calls.
That is a compact interface for selecting routes, enforcing identity and
controlling retries. Expression availability and policy composition depend
on the phase. An operator must know which context is populated and how
policies combine. Weaver can use the same idea of phase-scoped inputs in its
interfaces while keeping cross-request state and authority in the ledger.
[[https://github.com/agentgateway/agentgateway/blob/134897e1975fa26fa5c5b8ba45d720d05d3f7fb8/architecture/cel.md][CEL inputs]]
· [[https://github.com/agentgateway/agentgateway/blob/134897e1975fa26fa5c5b8ba45d720d05d3f7fb8/crates/agentgateway/src/store/policy.rs][Runtime contracts]]

** Budget consistency, concurrency and availability

| Architecture | Where the decision takes effect | Benefit and cost | Counterexample to qualify |
|--------------+---------------------------------+------------------+---------------------------|
| Weaver | Admission writes the plan and original claim, retains exposure and records workflow progression in one scoped transaction. The actual send has its own authority check. | Same-root requests have one deciding order. Independent domains can make progress separately. The transaction, contention and storage availability enter the admission cost. Uncertain effects can leave capacity held. | Two aliases of the same original root compete for the last reservation. Kill the owner after dispatch and before a reply. Verify total sends, retained exposure and exact recovery. |
| Praxis AI token limiter | Admission reserves estimated tokens through the configured backend, then settlement reconciles actual usage. A shared Redis/Valkey backend puts replicas on the same budget state. | It adds shared pre-admission control without an application workflow ledger. Estimates can diverge from actual usage. Failover, clock skew, window approximation and namespace changes affect the admitted total. | A primary acknowledges a reservation before async replication. Promote a replica that lacks the write. Measure whether the next admission exceeds the intended budget and classify the missing write separately from a lost reply. |
| Agent Gateway budget policy | The request checks accrued usage. Completed responses update local amount and pending delta. Flush atomically increments the persistent total. | This keeps database writes out of the request check and supports aggregated spend reporting. Concurrent arrivals can all observe usage below the limit before any finishes. Flush durability does not order these requests at admission. | Start a burst with one unit of budget remaining. Let all requests cross the check before the first completes. Count actual upstream calls, final accrued usage and database persistence separately. |

The Agent Gateway conclusion above is specific to the inspected API-key
budget path. Other rate-limit policies require their own test and backend
configuration. The Praxis documentation explicitly separates Sentinel recovery
from replication durability and says a dispatched operation with a lost reply
is not replayed. Weaver's native recovery tests establish the behavior of the
tested storage/transport cohort. Site failover under the same fault schedule is
an outstanding qualification.

** Retry, stream release and the point of no return

Praxis has the flexibility to transform an input and retry another origin.
Agent Gateway adds request and response retry predicates and a body replay
buffer with a byte cap. These are useful for availability when an upstream
operation is safe to repeat. Once a provider may have accepted a chargeable
invocation, an HTTP retry policy alone cannot recover the original effect.
Weaver binds the plan digest and actual destination, disables transport retry
and redirects in its guarded client, and distinguishes re-observing an
existing receipt from admitting another effect. This can sacrifice transparent
failover when an outcome is ambiguous. It makes the decision to spend again
explicit. The key test is the provider's invocation count, including attempts
whose replies never arrived.
[[https://github.com/praxis-proxy/praxis/blob/c3d2ae3628cf3167780e58c5e8b38580d0241399/examples/configs/traffic-management/retry-policy.yaml][Praxis retry]]
· [[https://github.com/agentgateway/agentgateway/blob/134897e1975fa26fa5c5b8ba45d720d05d3f7fb8/crates/agentgateway/src/http/retry/body.rs][Bounded replay]]
· [[file:../../crates/broker/src/provider/runtime.rs][Weaver final client]]

Content evaluation and release authority have different boundaries. Agent
Gateway's streaming guardrail accumulates a bounded SSE window and decides
whether to flush it. This can catch unsafe content mid-stream at the cost of
buffer memory, evaluation calls and time to first byte. The inspected Praxis
NeMo response phase evaluates completed response bodies and rejects streaming
requests when that phase is enabled. Its general SSE filter machinery remains
available for other chains. Weaver stages inert ranges and joins each actual
delivery with current authority and a one-use cursor. This prevents a queued
range from escaping after revocation. It incurs bookkeeping, backpressure and
validation cost, and it cannot retract a byte already admitted to transport.
An external content decision can become an input to the same release boundary.
It needs a digest and position binding before it can be reused for a range.
[[https://github.com/agentgateway/agentgateway/blob/134897e1975fa26fa5c5b8ba45d720d05d3f7fb8/crates/agentgateway/src/llm/policy/streaming_guardrails.rs][Windowed SSE guardrail]]
· [[https://github.com/praxis-proxy/ai/blob/f96d0114a995765793b1fb33f86f94ecc298eb08/docs/filters/ai_guardrails.md][NeMo phase]]
· [[file:../../crates/server/src/grpc_delivery.rs][Weaver receiver]]

** Workflow, state and reuse

Praxis AI has useful interoperability for Responses/Conversations, stored
history and replay. A configured agentic chain can bring tool results back to
inference. Agent Gateway provides an interoperable proxy for MCP tools and A2A
tasks, with session and transport responsibilities at the gateway. Weaver
assigns the workflow frontier itself to the governed runtime. A complete
release supplies a result, Scheme derives eligible work, and Rust commits
the corresponding claim, reservation and branch progress together. This can
keep a conditional join correct under competing triggers and restarts. It also
requires a stable result shape, attributable receipts and an explicit
workflow scope. Compare a join after one selected branch and one inactive
branch, rather than treating all three products' session IDs as equivalent.
[[https://github.com/praxis-proxy/ai/blob/f96d0114a995765793b1fb33f86f94ecc298eb08/docs/architecture/response-store.md][Praxis response state]]
· [[https://github.com/agentgateway/agentgateway/blob/134897e1975fa26fa5c5b8ba45d720d05d3f7fb8/crates/agentgateway/src/mcp/session.rs][Agent Gateway sessions]]
· [[file:../../crates/ledger/src/provider_workflow_choice.rs][Weaver branch and join]]

Weaver's retained ASCENT experiment reuses at most one completed session
for the same graph and replaces every dynamic input at the next cut. A failed
evaluation drops the retained session. This separates reuse of rule
preparation from reuse of a stale answer. The compiled entry selects it
through an explicit test switch. Any adoption claim needs the formal A/A and
retained A/B on one release, plus restart and withdrawal controls. Measure
owner queueing, cut replacement, derivation and the final reservation
separately so a gain in one component does not hide a shift in another.

** Integration and operational choices

| Requirement | Design to borrow or retain | Cost or qualification boundary |
|-------------+----------------------------+--------------------------------|
| Easy drop-in client migration | Borrow Praxis's protocol-first configuration, effective-config dump and runnable OpenAI/Anthropic translation examples. Define what Weaver's normalized request can preserve, then bind the resulting destination, codec and payload before final use. | Each translator can lose tool, usage, error or stream semantics. Conformance needs real client traces and a negative case for unsupported translation. |
| Kubernetes rollout and discovery | Borrow Agent Gateway's small resources, attachment model, Gateway API mappings and Helm-based delivery. Feed accepted resource changes into Weaver's existing source and publication owners. | Reconciliation and runtime authorization are separate. Require evidence that an observed Kubernetes object version cannot reactivate an older grant. |
| Latency and memory on ordinary traffic | Praxis and Agent Gateway place standard routing and request policy in their proxy runtime. Weaver can reuse immutable prepared artifacts, bound native buffers and group already buffered releases without changing the per-frame cursor check. | Compare time to first byte, inter-frame tail, peak buffer and CPU at the same offered load. Report transaction and guardrail overhead only for configurations that implement the corresponding behavior. |
| Audit and failure operations | Borrow stable metrics and scoped administrative status from both proxies. Use Weaver receipts for decision and effect evidence, with bounded telemetry for operators. | Telemetry may aggregate, lag or reset. An audit for ambiguous spend needs operation identity, a current source cut and attributable provider evidence. |
| Reusable policy and validation | Keep SysML allocation, native Build Packages, Scheme/POO composition and the Cedar/Lean boundary. Borrow explicit phase contracts and source-linked config examples. | Extra authority layers raise the verification and deployment burden. New adapters should inherit existing source, admission and release tests before receiving the same guarantees. |

The strongest near-term Weaver investment is a narrow governed path with
evidence from source publication to external bytes, plus reusable adapters for
the proxy ecosystem. Praxis and Agent Gateway show the cost of building
client compatibility and Kubernetes integration well. Weaver should expose
its stronger application guarantees on the paths that actually implement
them and list each adapter's coverage alongside them.

* Default Gateway storage

The default Gateway deployment has one authoritative Turso store.
Persist accepted source and policy revisions, claims, exposure,
delivery intervals and settlement in that store. A provider run
retains its bound request plan, including the body, while queued or
unresolved. Completion reduces the plan to its original ceiling in
the transaction that records terminal state. The run digest and
independently recorded claim still participate in exposure checks.
Historical full plans remain readable by the same ceiling projection.
Resumable message streams retain their contract payload. Provider SSE
response ranges remain in bounded runtime buffers while durable
release records hold sequence, length, digest and state. Workflow
selectors persist the decoded route and result commitments.
Operational counters and diagnostic exports stay separate from
the deciding transaction. [[file:../../dev/sysml/WeaverExecution.sysml][Storage ownership model]]

Measure logical record bytes and physical database and journal bytes
separately. Terminal compaction reduces the live record and leaves
physical reclamation to the storage engine. Derive any future
analytical view from approved exports.

identity scope and concurrent arrival schedule. Freeze the product revisions,
feature sets, configuration, backend topology and negative controls. Record
whether each configuration supports the scenario before comparing its result.
