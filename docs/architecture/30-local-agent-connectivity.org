* Decision and current boundary

Reuse Magpie's user operation surface, running local host and Agent-specific
configuration ownership for the first integration stage. Connect a fixed Weaver
backend through a supported interface. A later unified distribution may deliver
those components in one installation; it does not make the local host disappear.
The embedded Marlin model client remains an independent deployment choice.

The normative design is [[file:../../dev/sysml/AgentConnectivity.sysml][AgentConnectivity.sysml]], linked from =Project.sysml=.
Its requirements, state machine, typed ports and acceptance cases are planned
contracts. Strict model analysis checks their structure and trace coverage;
it does not establish a working Magpie adapter, HTTP endpoint or installer.
Existing runtime, credential and source qualification retains its own evidence.

The upstream reference is Magpie revision
=eae77a48a025c5e3f005301ee885cd20b74b0ece=, inspected on 2026-11-20:
[[https://github.com/yetone/magpie/blob/eae77a48a025c5e3f005301ee885cd20b74b0ece/docs/integrating.md][integration contract]],
[[https://github.com/yetone/magpie/blob/eae77a48a025c5e3f005301ee885cd20b74b0ece/docs/subsystems/agent-wiring.md][Agent configuration ownership]],

The first request path is:

Stock Magpie's standard HTTP provider is the first public join. Existing Go/RPC
can be reused internally; it is not an existing Magpie extension. Both projects
have Go =internal= packages that cannot simply be imported across repositories.
An in-host RPC integration requires a maintained Magpie-side adapter and is a
separate future choice. Select one external binding per profile. HTTP ingress
and internal RPC are different layers, not competing route authorities.
This stage includes Magpie's proxy and the Weaver backend;
performance accounting includes both and the selected transport adapter. Magpie
must remain on a fixed Weaver provider for a Weaver-backed profile; its direct
provider/account fallbacks cannot silently bypass Weaver. Independent direct
Magpie profiles remain visibly separate and have a different enforcement scope.

* Connection lifecycle and invariants

The =AgentConnectionLifecycle= state machine models disconnected, preparing,
applying, verifying, connected, drifted, unavailable, restoring and
recoveryRequired. Events represent checked owner outcomes, not UI assertions.
State is scoped to the selected profile/generation. A refused rebind preserves
and reports the prior observed configuration; Disconnected does not mean that
the CLI cannot use a different provider.

1. Prepare the chosen endpoint, protocol, model and credential reference.
   Read model choices from the backend's source-versioned, caller-scoped
   catalog through the chosen interface (=GET /v1/models= for HTTP); preparation
   rejects a stale selected generation.
   Require host/backend readiness before changing the CLI configuration.
2. Reuse the config owner's protected ownership record and original intent.
   Qualify intent-before-write recovery instead of presuming the upstream
   applied/stash records already provide it. Check file identity and expected
   owned fields, then atomically edit through that same owner.
3. Verify the connection before showing Connected. A failed verification
   requests owned-field restoration; it never switches to a direct vendor.
4. Report external changes as drift. Preserve unrelated fields, comments and
   formatting. Reconciliation of a conflicting owned field requires an explicit
   user choice. Disconnect cannot blindly restore an old whole-file snapshot.
5. Inspect an unknown write using its original intent. A recovered applied
   connection goes to verification; a verified restoration goes to Disconnected;
   a safely pending original restoration resumes restoration. An unresolved
   outcome stays in recoveryRequired, rather than replaying the write.
6. Report host/backend loss as Unavailable. Reconnection requires readiness of
   the same selected generation. The status is observed by a live or reopened
   operation surface; a terminated desktop process cannot display it. Reopen
   the local config owner after whole-host loss. Disconnect/restore must work
   without the gateway or upstream network. Update/uninstall restores owned CLI
   settings before removing the host.

The three credentials have separate custody: CLI-to-local-host,
host-to-Weaver and Weaver-to-provider. Application names and session headers
are observations. A shared host credential cannot establish distinct CLI users;
narrower identities require explicit authenticated delegation. Reuse existing
credential/OAuth owners and secret references. A managed distribution defaults
subscription discovery off through Magpie's existing control. An existing user
host retains its user's privacy choices; the Weaver adapter does not import
discovered accounts. Exporting provider secrets or enabling remote binding is
a separate explicit configuration, not a consequence of installing the adapter.

All transformations precede the final request commitment. No reply delivered
to the client is not evidence of no provider execution: existing unknown-budget
holds and final-use checks remain decisive. Optional enrichment and mandatory
security checks retain distinct failure behavior. Scheme derives on bounded
fact changes; ordinary stream events do not call back into the semantic VM.

runtime evidence only after execution. Complete lifecycle and identity cases

* Rich-event contract implementation

=crates/contracts/src/provider_turn.rs= now defines a bounded version-1 event
with text, thinking and terminal payloads. Terminal observations retain tool
IDs/arguments, response identity, reported usage and opaque Responses or
Anthropic continuation blocks. Duplicate keys, unknown versions, duplicate tool
IDs, incomplete tool finishes and oversized payloads are rejected. Debug output
does not disclose thinking, tool arguments or retained continuation blocks.
Construction and serialization confer no execution or publication authority.

a second policy interpreter; its existing text-only execution API still rejects

* Terminal token-category handoff

=TokenCategories= in the existing SDK partitions ordinary input, cache reads,
cache writes and inclusive output. OpenAI's input total includes cached reads
and writes, so ordinary input subtracts both. Claude reports those three input
categories separately; cumulative message deltas replace their earlier values.
See the vendor definitions in
[[https://developers.openai.com/api/docs/guides/prompt-caching][OpenAI prompt caching]] and
[[https://platform.claude.com/docs/en/build-with-claude/prompt-caching][Claude prompt caching]].
The codec checks underflow, overflow, invalid numbers and inconsistent totals.
Reasoning output is part of inclusive output and is not charged a second time.

contract retains raw reported usage and an optional named category record;

passes the same four values to =complete_provider_with_result=; no second
metering store or price source is introduced. Native TLS tests read the resulting
=provider_terminal_usage= rows and compare them to the released payload, while
asserting the original hold is unchanged. Unknown usage creates no fabricated
zero report. The existing issuer, quote and ledger own settlement.

* Session scope contract and next deciding transaction

=crates/contracts/src/provider_session.rs= now defines source-owned
=ProviderSessionScope=, untrusted =ProviderTurnSubmission= and the named
=ProviderTurnDerivation= returned by Scheme. The scope reuses =Task= limits,
=ProviderProfile= interpretation, =PublicationKey= and =DomainBinding=.
Its template has exactly one unbound node and 1--64 allowed turns. Normal
=Task::validate= still rejects that template: it cannot be registered or sent
until an exact derived original is independently checked.

The turn family derives from the scope commitment and retry key, excluding
request bytes. A changed retry body therefore changes the command commitment
while retaining the conflicting identity; it cannot silently become another
original. A changed source scope changes the family. Each derived original
retains the source's principal, profile, models, routes, reservation bound and
total budget. Its origin changes, but budget/history domains do not. This is a
pure contract boundary, not a new admission service or send owner.

Four contract tests include a 64-case property and adversarial internally
consistent route, profile, quota, history and wire substitutions. The minimized
template-validation regression is retained as a replayable proptest seed.
=SessionTurnAdmission.qnt= records the transaction's design obligations:
16 named cases and a fixed 256-trace, 30-step safety run, seed 293. Its missing
parent-fact-binding counterexample is deliberately unsafe. This abstract model
does not substitute for the native ledger acceptance below.

The source lane join must use these existing ledger steps; step 2 remains open:

1. Register the exact authenticated source Session scope and capture its source
   epoch, publication, parent fact floor/revision/snapshot and intent prefix.
2. Let the existing Scheme/POO/gerbil-ascent owner select a bounded concrete
   turn outside SQL; use =ProviderSessionScope::admits= for independent checks.
3. In one ledger write scope, compare the exact captured coordinates, retain
   the unique retry decision and finite turn count, register the original with
   the existing shared domains, and persist its parent fact-scope linkage.
4. Reuse that linkage at existing final-send and range-release guards. Checking
   only the generated family would miss withdrawal of the parent Session;
   independent origins are not aliases of the parent's execution origin.

No HTTP compatibility route is enabled until these runtime joins are tested.
The bounded runtime acceptance remains two changing turns/tool results, replay
with changed bytes, concurrent shared-budget exhaustion, restart and hard-fact
withdrawal with zero unauthorized provider calls. Keep four workers and one
watchdog per package; do not expand this into repeated cold-start experiments.
