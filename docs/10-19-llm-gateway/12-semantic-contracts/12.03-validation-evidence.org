* Checked scope

The runner (retired Python driver) compiles nine Lean modules in a fresh directory and checks the
new [[file:../../../dev/proofs/lean/LlmSemanticContract.lean][Lean]] and [[file:../../../dev/proofs/quint/LlmSemanticContract.qnt][Quint]] models. Commands and raw outcomes are in
[[file:../../../dev/proofs/evidence/llm-semantic-contract/commands.json][commands.json]]; the [[file:../../../dev/proofs/evidence/llm-semantic-contract/receipt.json][receipt]] records final counts and limitations. Preliminary
compiler diagnostics are retained separately from final successful elaboration.

The model concerns one declared attempt scope with arbitrarily finite Lean
argument fragments, output events and tool-call keys under configured limits.
Quint uses three candidate call keys, a two-call cap and four argument units.
Payload projection excludes private history/budget domains and response-mode
metadata, which are checked separately in the sealed internal envelope.
The baseline has one candidate per attempt and rejects implicit candidate fanout.
Identifiers/digests/argument units abstract real bytes, hashing and JSON parsing.
The codec projection and observation predicates are supplied owner contracts.
They are not proofs of equivalent model behavior, a native Cedar evaluator or a
real provider's compliance.

* Composition and prerequisites

=Audit= preserves valid sealed projection, source-bound validated outputs,
qualified tool proposals, per-call argument bounds and zero implicit tool effects.
=finite_call_count= separately proves the configured call-count bound. A release
transition requires current owner epoch, committed winner, exact event ordinal,
current disclosure Policy and an open stream. A validated-document scope must
release a complete document, never an ordinary partial text event. Its response
mode and private history/budget context remain in a separately sealed internal
envelope rather than requiring transmission to the provider. Raw tool fragments can be retained
as data but cannot become executable arguments in this model.

=ChildCall= carries the exact guarded invocation of the existing attempt ledger,
including its initialized prior run, actual record, current target/view/epoch,
zero call slot and child authorization. =refines_actual_child_invocation= produces
the actual prior-module transition. =EncodingBridge= binds actual wire fields and
canonical payload to that record and checks semantic projection. The composed
invocation retains the prior module's budget invariant. This is an explicit typed
boundary proof; it is not a mechanically verified asynchronous product of codec
state, all child attempts, winner CAS, byte ranges and cross-store settlement.

The supplied =Scope= must come from the authoritative original task sponsorship.
Matching a caller-supplied scope would be insufficient. The current bridge proves
metadata equality with that supplied scope and retains the actual child's budget
invariant; it does not derive its history/budget domain identifiers from the
upstream domain registry. The final =sendValid= owner must check that root-to-scope
binding, including response mode, against the authoritative task record. A fully
checked registry-to-scope attestation bridge remains an explicit extension.

The new semantic state machine's =admit= guard and a =ChildCall= witness must be
joined in one final broker transaction at runtime; neither is permission to run
the other independently. Qualified codec projection, injective name mapping,
strict parser/schema checks, authoritative completion, atomic consumption,
rollback-safe recovery and current winner/release ownership remain premises.
An =EncodingBridge= cannot be manufactured from a body digest alone. Collision
resistance and exact native byte ownership are not proved in this model.

The semantic projection covers selected fields; attachment resolution, role
precedence, candidate mappings, header semantics, full tool-effect admission,
complete document buffering and native total-memory accounting require refinement.
The model proves count/length limits, not allocated native memory or liveness.
Usage continues through the original-root settlement contracts from category 11;
this change cannot clear unknown costs or authorize new account domains.

These deliberate unsafe actions are excluded from =step=. Their six exported
[[file:../../../dev/proofs/evidence/llm-semantic-contract/itf][ITF traces]] are independently decoded and inspected. Guarded scenarios also
reject alias collisions, tool-set expansion, parallel/choice/schema weakening,
wrong history/budget domains, out-of-order fragments, overwritten arguments,
duplicate proposals, truncated streams and old-worker release.

* Runtime acceptance and source receipts

Use representative golden request, response and stream fixtures across each
qualified provider/codec profile, including negative fixtures. Verify actual
bytes and headers, tool aliases/history round trips, unsupported constraint
rejection, strict JSON/parser behavior, truncation/refusal semantics, interleaved
calls/candidates, policy changes during streaming, queue crashes, delayed callbacks
and restart recovery. Bind every receipt to exact source and runtime identity.
Add matched first-token/throughput/memory controls; no performance claim follows
from these local formal checks.
