finite Lean child allocations. Quint uses four child slots, two eligible models
and a fixed root allowance. Its finite fixtures do not establish unbounded model
checking. The immutable profile and =Owner= predicates model trusted contract
inputs, not a native Cedar evaluator or durable SDK implementation.

* Proof assumptions and composition limits

=initialized_safe= preserves maximum allocation, sum of maxima, one call per
child, closure readiness, ready winner and bounded aggregate charge. The
observed-charge bound follows from that invariant. RootSponsor explicitly binds
the root allowance to an existing admitted claim and shared-account booking.
The old root =sends <= 1= statement concerns the admitted root offer; it is not a
claim that multiple remote provider generations execute exactly once.

The new child ledger is a distinct extension: the previous routing dispatch
transition remains disabled in its route wrapper. Child invocations use a new
operation contract. The original root reservation must remain booked throughout the child run as
a coupling assumption; the standalone child =Run= does not prove that an external
account owner retains it or rejects rollback. A task sponsor predicate cannot be fabricated from a
provider-specific old token. The source bridge composes abstract root authority
and cost bounds; it does not prove that native storage, Cedar, SDKs or providers
implement the predicates. Lean's charge theorem proves an aggregate upper bound;
Quint additionally checks the exact sum of accepted usage slots. A general Lean
sum-of-usage equality refinement remains future work, not an established result.

Atomic allocation/consume, qualified negative/usage observations, current release
policy, durable unique slots and rollback-safe owner epoch are explicit premises.
Logical retirement is not proof of remote non-execution. The range model's
consumption/fencing properties must be connected through exact root/winner/range
bindings at runtime. This change does not mechanically verify the asynchronous
product of child ledger, all range transitions and external settlement stores.
No liveness or remote exactly-once result is claimed.

* Runtime acceptance still required

Test every crash boundary with real durable stores and provider adapters: lost
allocation/invoke acknowledgement; pre/post queue crash; automatic SDK retry;
redirect; prefix race; partial stream failure; late receipt after owner restart;
loser cancellation with continuing billing; duplicate final usage; root account
commit loss and rollback. Preserve unknown holds and exact source identities.
A finite model pass or successful Lean compilation is not native integration,
operational recovery, throughput evidence or an end-to-end provider guarantee.
