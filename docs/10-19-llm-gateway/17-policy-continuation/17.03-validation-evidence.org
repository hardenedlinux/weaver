* Proof composition and explicit premises

=WinnerSafe= relates every committed family publication to exactly the same
stable winner and requires that winner to exist in the source log. The proof
excludes a second family publication, including after response loss. Source
publication remains an actual category-16 step, so its parent/fence/current-Policy
checks and durable-prefix laws still apply. Every approval retains the original
semantic tuple, and every admitted alias names the original canonical family.

The source projection retains original claim uniqueness, profile interpretation,
allowance, account domains and unknown-usage settlement constraints. Original
staged membership survives every source-changing step. Neither inspection nor
alias registration modifies execution authority.

The immutable =original= parameter and =owner.familyOf= represent authenticated
canonical source registration. Their correct native issuer/tenant/operation
binding is an explicit premise; a caller-controlled family classifier would
invalidate this proof. Qualified complete-family absence, current reauthorization,
durable approval, alias authentication and non-rollback source/winner persistence
are also owner contracts. Atomic family-winner/source publication is a required
native refinement, not an implemented distributed transaction.

The alias model checks identity/effect separation for protocol tags. It does not
verify MCP/A2A/ACP/AG-UI/ASP wire schemas, parsers, transport authentication,
OAuth, client permissions or event delivery. Those require independent adapter
acceptance. No liveness, full multi-tenant/multi-domain product, native storage,
remote exactly-once or performance claim is made.

Unsafe actions are excluded from =step=. [[file:../../../dev/proofs/evidence/llm-policy-continuation/itf][ITF traces]] are independently decoded;
old-permit evidence must show actual earlier issuance and a newer committed Deny.
A negative control can deliberately remove a linked pair of enforcement guards;
it does not demonstrate that removing any unrelated single guard is sufficient.

* Native acceptance

Race original/candidate publication with competing families, current authorization
changes, ledger writes and owner restart. Lose replies at candidate staging,
approval and final winner/publication commit. Query by the full canonical family
and exact payload; do not classify unknown as conflict from local absence. Keep
old worker handles and queued confirmations alive. Restore independent producer,
approval, winner and source-log projections; require exact current-prefix recovery.

Exercise MCP reconnect, A2A task recreation/stream resubscription, ACP session
resume and AG-UI replay against the same original claim, family and account domains.
Verify forged/new protocol IDs cannot create a family, erase original pending or
refund unknown work. Preserve parser/source fingerprints for ASP read proposals.
Collect source-bound native receipts separately from abstract proof acceptance.

* Local validation result

The runner checks 25 command routes: 14 Lean modules, Quint typechecking,
42 scenario controls (34 guarded cases and eight negative controls), focused
exported counterexamples, seven sampling routes and 45 category-16 regression
controls. Each sampling route uses ten samples and at most 30 post-initializer
steps with seed 181. These 70 samples are bounded simulation, not exhaustive
temporal verification.

The new Lean module checks 18 printed declarations without =sorryAx=. Twelve
four-artifact rows resolve to passing Quint cases, printed Lean statements and
core D2 nodes. Independent trace decoding checks actual staged candidates, the
existing winner hidden by reply loss, and the real old permit followed by newer
Deny. Source review includes 33 pinned blobs across POO Flow, Cedar, agentgateway
and ASP, plus seven official protocol references for the interface taxonomy.
Native storage and protocol conformance remain separate acceptance obligations.
